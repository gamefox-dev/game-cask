# Shared x87 execution model (lane K3)

Both guest widths use `x86_x87.c` in interpreted and generated/predecoded execution. No game-specific
paths or host FPU assumptions. `X.fpu` (eight physical registers, two-bit tags, TOP, control/status)
is part of `x86_cpu_t`; the scheduler copies it with every guest context. Lazy reset is FINIT state
(037F control, empty tags, zero status). FINIT/FNCLEX do **not** change MXCSR.

## Precision

Registers and m80real operands preserve the exact 64-bit explicit significand and 15-bit exponent/sign.
`x86_ext80.h` uses integer significands, 128-bit intermediates, sticky-bit shifts, long division and
integer square root. ADD/SUB/MUL/DIV/SQRT round once to control-word PC=24/53/64 with RC=nearest-even,
down, up or truncate, retaining extended exponent range. Reserved PC=01 is treated as 64, not a
portable architectural promise. IEEE binary32/64 stores use their destination precision/exponent
and RC; m80 stores do not round. FRNDINT honors RC independently of PC. FSCALE truncates ST(1) exactly
and retains 64 significand bits; FXTRACT and FPREM/FPREM1 retain ext80 precision. Partial remainder
reductions set C2 and permit caller iteration; complete reductions set C0/C3/C1 to magnitude quotient
bits 2/1/0. Constants use their architectural ext80 encodings and RC, independently of PC.

**Reviewer-approved transcendental boundary:** F2XM1, FYL2X/FYL2XP1, FPATAN, FSIN/FCOS/FSINCOS/FPTAN
convert inputs to nearest binary64, use the installed Zig 0.13 WASI musl libm, and convert the binary64
result to ext80 exactly. This is **not** correctly rounded 80-bit transcendental arithmetic. The input
conversion error is at most 0.5 binary64 ULP for normal representable inputs; known-answer tests allow
4 binary64 ULP on their finite, well-conditioned cases (trig tests also check stack order). No global
4-ULP bound is claimed near singularities, with ill-conditioned argument reduction, or when ext80
inputs/results exceed binary64's exponent range. FYL2XP1 uses log1p (not log2(1+x), which loses tiny x).
F2XM1 uses expm1(x*ln2). Trig |x| >= 2^63 sets C2 and leaves ST(0) unchanged. F2XM1 outside [-1,1]
(an architecturally undefined-result domain) faults explicitly rather than returning an invented result.

## State and exceptions

FXAM distinguishes empty/unsupported/NaN/normal/infinity/zero/denormal and reports sign in C1.
FCOM/FUCOM, pop variants, FTST and FCOMI/FUCOMI variants use exact comparisons; unordered codes and
SAHF-visible FNSTSW AX are preserved. FCOMI clears OF/SF/AF as required. FCMOV reads integer condition
flags. FFREE/FXCH/FLD/FST(P), integer loads/stores, FLDCW/FNSTCW, FNSTSW AX/m16, FINIT/FNCLEX and FWAIT
share the same state.

Masked invalid, denormal-operand, zero-divide, precision, overflow and underflow are sticky. Stack
faults set IE/SF and overflow versus underflow C1. Basic arithmetic reports rounded-up C1; tiny inexact
results report UE/PE (tininess after rounding). Signaling NaNs are quieted with IE; quiet NaNs propagate.
Unsupported unnormal ext80 operands return indefinite with IE. Exact special results include signed
zero and infinity. Undefined condition bits are not promised; no host floating environment is consulted.

Unmasked x87 exceptions currently stop with an explicit kit fault (and ES/B), **not Windows SEH #MF
exception delivery**. FLDCW preserves control bits; FWAIT checks pending unmasked exceptions. Pending
exception timing, FP instruction/data pointers/opcode, ENV/SAVE/RESTORE and FXSAVE/FXRSTOR, packed BCD,
and exact transcendental PE/UE/OE flags are not delivered here. These are visible remaining capability
boundaries, not successful no-op implementations. General Windows FPU-context APIs are outside this lane.

## Evidence

`tests/unit/x87.test.ts` builds original synthetic PEs for i386 and AMD64, lifts each, and executes
known answers in both generated and decoder-driven modes. It checks raw ext80 bits, stack/status,
all arithmetic directions/destinations/pop forms, real/integer memory forms, RC/PC against independent
BigInt rational rounding, integer-square-root references, exceptional classes, binary32/64 rounding,
transcendental answers, and actual scheduler context isolation. No target executable bytes are used.
The small WASI harness asserts no WASI imports, just as the existing CRT fixture checks the real profile.
