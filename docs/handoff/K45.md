## Approved boundary and implementation

Systematic lifting remains the default. The separately selected engineProfile path requires
operator authorization **outside port/** bound to both game id and whole runner SHA-256:
trial:brief --allow-engine-profile or .engine-private/authorizations/<id>.json.
Config allowed:true cannot authorize itself; stale/cross-game grants fail. Operator grants must
not be created/edited by the porter. There are no BGT ABI or lifter/profile-semantic changes.

* tools/engine/framework.mjs + profile.schema.json: exact pairing/config, adapter registry,
  hash-bound inspect input, extraction/build orchestration.
* godot3.mjs: PCK v1 bounds, UTF-8/path, range/overlap and MD5 validation; trailer-only embedded
  discovery and offset rebasing without rewriting assets/scripts; explicit blockers/warnings.
* runtimes.json + runtime.mjs + offline-zip.py: offline-only archive/member/notice pins, strict
  plain ZIP entries, safe extraction, atomic provisioning and re-verification against allowlist.
* shell.mjs + browser-adapter.js + server.mjs: official runtime/unchanged pack, observation-only
  test subset, integrity-allowlisted local server/CSP; unsupported deterministic BGT features fail.
* Standard build:port/test:port and engine:probe have end-to-end CC0 dispatch coverage, including
  operator brief, no-runtime skips and malformed provision failures. Existing lifting dispatch stays separate.
* Trial reports identify execution path, runtime and hashes; leakcheck protects engine material.
  Runtime archives, runtimes, packs/builds remain private/local and uncommitted.

## Review resolution

Earlier decisions #415/#415a/#416 approved the separate path, outside operator gate and pinned notices.
31bb910 binds grants to game/runner hashes. 9482fb1 hardens ZIP entries, adds public dispatch/fault
coverage and implements decision #423: retain a Chromium ERR_ABORTED as **canceled-after-complete**
only with HTTP 200, EOF observed at cancellation, matching positive Content-Length, complete bytes
and the allowlisted SHA-256. Partial/early/wrong-hash/HTTP-error failures remain fatal.

Re-review vK45e on 9482fb1 reported one issue (#427): selecting reader evidence by URL could borrow
a prior complete request after another same-URL fetch failed before headers. Fixed in **6364a01**:
unique per-fetch capture identity is allocated before fetch, carried in a same-origin diagnostic
header and bound to the Playwright Request; no URL lookup. Reviewer approved this approach with
capture-only/same-origin scope. Production shells/official runtime bytes are unchanged, tokens are
not exposed to game/engine, cross-origin fetches get no token or CORS preflight. Regressions cover
second same-URL requests aborted before headers and mid-body, header scope, and uninstrumented
production shells. The production-shell test adds one expected no-runtime skip to dispatch coverage.

Reviewer reported 120/120 engine repetitions, 36/36 focused units, authorization/ZIP/extraction and
HTTP 503 reproducers green on 9482fb1 aside from #427. Final acceptance boundary:
**vK45 was blocked by the provider filter; vK45b FAIL led to the authorization/ZIP/cancellation
fixes; vK45e FAIL (#427) led to 6364a01, then coordinator delta review accepted 6364a01 and closed
#427.** The coordinator checked pre-fetch token/record allocation, token-only lookup,
unchanged cross-origin/production behavior and both abort regressions. This is coordinator delta
acceptance, not a fabricated fresh vK45 full-suite pass. No external Tier 2 green claim is made.
