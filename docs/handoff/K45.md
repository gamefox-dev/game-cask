# K45 — engine profiles / Godot 3

## Approved boundary

Reviewer approved the separate engine path with explicit opt-in (engineProfile.allowed=true),
private runtime/pack/build storage, path/runtime/hash trial reporting, and an observation-only
browser adapter. Systematic lifting remains the default. No BGT ABI or lifter/profile semantics
changed. A later reviewer decision supplied official Godot 3.5.3-stable LICENSE.txt and
COPYRIGHT.txt; both are separately pinned and required at provisioning/build time.

## Implementation map

* tools/engine/profile.schema.json and framework.mjs: exact pairing/config validation, adapter
  registry, detection over inspect JSON with current-byte hash binding, extraction/build orchestration.
* godot3.mjs: PCK v1 bounds/UTF-8/offset/overlap/MD5 validation, trailer-only embedded discovery,
  standalone offset rebasing, runner version/build corroboration, explicit unsupported blockers.
* runtimes.json, runtime.mjs, offline-zip.py: offline-only archive/member/notice hash allowlist,
  safe ZIP extraction, atomic provisioning and re-verification. No runtime files committed.
* shell.mjs/browser-adapter.js: official runtime + unchanged pack boot; screenshot/input/RAF
  observation subset; unsupported BGT deterministic/peek/savestate features fail explicitly.
* server.mjs: integrity-checked allowlisted files, MIME, isolation when required, local-only CSP.
* build:port selection and test:port choose a separate engine project; existing pipeline branches
  remain unchanged. engine:probe reuses makeProbe with an alternate URL. Trial records include path,
  runtime id, source/pack/runtime/member hashes. Leakcheck covers local engine material.
* tests/fixtures/engine: original CC0 ECFG/scene/GDScript/PCK and non-executable runner writer.
  tests/unit/engine-profile.test.ts: parser, policy, inventory integrity, server and leak regressions.
  tests/engine/godot3.spec.ts: provisioned-runtime input/pixels/screenshots/timing; absent runtime skips.

Detailed operator workflow and authenticity/licensing limitations: docs/engine-profiles.md.
No engine CPU/GPU performance claim, game compatibility claim, iPhone verification, or runtime
redistribution clearance follows from the CC0 smoke. Static detectors are conservative but not
complete for compiled/dynamic scripts; exact signatures can be forged. Follow-up adapters need
