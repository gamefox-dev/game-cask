## Rejected experiment

A scratch-only emitter variant made all boundary register stores conditional on the dirty mask, including
interior/fault boundaries. It preserved checksum, lifted/interpreted trace identity and zero interpreted
instructions. It did not establish a speedup: sequential fresh-instance medians were 11.878 ms Asyncify and
11.090 ms JSPI versus corresponding baseline 11.679 and 11.041 ms (noise/slight regression). It also
requires careful fault-boundary auditing, so it is not retained. The working emitter is restored unchanged.

## Continuation implementation and measured items

K31/I15 was merged before implementation; accounting remains default-off and no ABI, trace schema, or retirement code changed. Three independent codegen items are retained:

1. **Full-flag ALU helper inlining.** The xl_alu_full wrapper is now always-inline around the existing liveness-aware xl_alu; the emitter still emits the same operation and exact cold fault replay recipes.
2. **Operand pointer fast path.** xl_pointer_checked now folds the common same-page mapped/unprotected case and falls back to the full-width, cross-page permission check. No host pointer crosses a call, fault, growth, callback, or suspension.
3. **Scalar shifts.** SHL/SAL/SHR/SAR sites use an always-inline xl_shift; rotates retain x64_shift. The helper preserves the existing deterministic oversized-count and undefined-flag choices.

Existing tool-binary and header dependency fingerprints invalidate affected lift chunks, objects and linked/Asyncify artifacts; no ABI or cache schema/version change is needed. The new unit regression copies the actual x86_lift64.h into a temporary tree, mutates only its ALU return for an isolated exported probe, and requires one object recompile, a header miss reason, changed linked/JSPI/Asyncify hashes, a cold postprocess, then fully warm reuse. The production header is never mutated. A tiny i386 pipeline avoids needing an AMD64 relocation table for this build-cache-only check; the exported probe compiles the real AMD64 helper under X86_WIDE_CPU.

The sustained CC0 variant warms 30 updates, then times 300 updates with dispatch work on every Sleep. Nine alternating same-process fresh-instance pairs follow one discarded pair, in each suspension mode. Deltas are candidate minus baseline in milliseconds; negative is faster.

The earlier startup-inclusive ALU sample is retained: JSPI -3.06 ms, while Asyncify was contaminated by strong first/second ordering. The sustained run resolves that boundary. All sustained A/B artifacts had equal lifted/interpreted 300-frame oracle hashes in both modes, zero interpreted instructions and no stubs.
