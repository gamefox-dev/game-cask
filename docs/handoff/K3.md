## Q3: implemented contract and accepted precision boundary

`platforms/x86/x86_x87.c` is shared by i386 and AMD64 interpreter and generated fallback execution.
`x86_ext80.h` implements exact ext80 storage, integer-backed ADD/SUB/MUL/DIV/SQRT, comparison and
single rounding at PC=24/53/64, all four RC modes, extended exponent range and binary32/64 stores.
All register/memory/integer subtract/reverse/divide/reverse forms and destination/pop variants are
covered, plus arithmetic loads/stores/exchange, FXAM, FNSTSW AX/m16, FLDCW/FNSTCW, FINIT/FNCLEX/FWAIT,
FCOM/FUCOM/FTST and pop/I variants, FCMOV, FFREE, constants, FRNDINT, FSCALE, FPREM/FPREM1, FXTRACT,
F2XM1, FYL2X/FYL2XP1, FPATAN and FSIN/FCOS/FSINCOS/FPTAN. Status, tags, TOP and control are in
`X.fpu`, so the existing scheduler's whole-CPU copies isolate per-thread FPU state. FINIT does not
reset MXCSR. Stack faults, NaNs/signed zeros/Inf, condition flags and integer-store exception priority
have known-answer regressions. Recurring precision exceptions are events, not inferred sticky-bit changes.

**Reviewer decision:** exact basic arithmetic/storage/control, but **binary64-accuracy transcendental
results are accepted**, with explicit error/conditioning/exponent limitations. Implemented using the
installed Zig 0.13 WASI musl libm; FYL2XP1 uses log1p to preserve small input. Exact ext80 comparisons
control trig range/stack behavior, not rounded binary64 arguments. Full model: `platforms/x86/X87.md`.
No globally correctly-rounded ext80 transcendental claim or universal 4-ULP bound.

**Still bounded:** unmasked exceptions stop with an explicit kit fault/ES/B, not Windows SEH #MF
context delivery; precise pending-exception timing, FP pointers/opcode/environment save/restore,
FXSAVE/FXRSTOR, packed BCD and exact transcendental PE/UE/OE reporting are not delivered. Out-of-domain
F2XM1 (architecturally undefined result) faults instead of returning an invented result. No Windows
FPU-context API expansion. These limits must remain visible when resuming an engine trial.

## Q4: analysis population and conservative pointer rejection

- Final census is rebuilt from **retained function-instruction membership**; overlap contributes once
  per owning function, not globally once per VA. Per-function FPU/unsupported totals and census now
  share that population; undecodable addresses are counted separately. `.pdata` scans count FPU too.
- AMD64 runs the classify/reanalyze loop instead of returning before pruning. Entry/export/direct-call
  provenance upgrades already discovered pointer entries. `.pdata` ranges are protected.
- AMD64 NULL rejection requires an aligned complete eight-byte zero payload and weak pointer-only
  provenance. Rejections expose address, relocated/immediate seed kind and `zero-pointer` reason.
  Ambiguous two-zero-byte, printable-code and unsupported/UD2 streams are **not** rejected on AMD64.
  Existing PE directory/import-name checks remain; i386's pre-existing heuristic policy is unchanged.
- Reanalysis clears import-site counters. Census is rebuilt after final pruning; fixed-point analysis
  does not stop with a newly rejected seed still present in its final function list.

Synthetic tests protect direct-call and unwind functions, UD2 and printable callbacks, exercise both
LEA and DIR64 NULL-seed provenance, and assert FPU census/per-function sum identity. This is a
conservative static policy, not a proof that every possible executable byte stream is data/code.

**Target evidence only, no target analyzer run:** supplied trial counts were **49,956 functions,
7,084,076 instructions**, FPU totals **80** versus census **459**, zero data-seed rejections. These
are historical input measurements, **not recalculated post-fix coverage**.

## Q5: bounded metadata continuation and unwind facts

`tools/x86/pe-metadata.mjs` diagnoses empty RUNTIME_FUNCTION entries and continues through the
size-bounded table, including empty ranges whose unwind field is nonzero. Malformed records are
per-index diagnostics/errors, not a table-ending exception. Valid ranges survive malformed unwind
metadata with `unwindError`. UNWIND_INFO exposes version/flags/prolog/code slots/frame fields, raw
code slots, aligned chained record or handler/data RVAs. Section mapping honors virtual size rather
than accidentally treating a huge raw overlay as virtual metadata. File/image/range/alignment bounds,
record cap, inconsistent directory pairs and trailing record-size errors remain explicit.

**Target evidence only:** supplied bounded audit reports **49,778 entries = 3 empty + 49,775 nonempty**.
The committed independent synthetic fixture produces those counts; its nonempty records repeat a
known valid range/unwind encoding, so this is continuation/count evidence, not a diverse target-table
reproduction. Other fixtures cover reversed/out-of-image/unbacked records, unwind errors, chained
alignment, handler tails and continuation. Recursive chain-cycle/UWOP semantic validation is not a
claim of this static metadata tool; raw code slots are exposed for consumers.
