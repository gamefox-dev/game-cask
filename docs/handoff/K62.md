# K62 — viewports past the target, reversed depth range, provoking vertex, byte indices, packed varyings, GL 3.3 limits

Branch `kit/lane/K62`, base `d663f12` (K61 head). CC0 fixtures only; no game files or installs. Network: one fetch of
the public OpenGL 3.3 core specification PDF (Khronos registry) for the minimum table and provoking-vertex table.
Evidence: `/Volumes/CaskWork/lanes/scratch-K62/` (`e2e-*.log`, `unit-*.log`, `e2e-raster-neg.log` = the negative
control, `devprobe.json` = M4 adapter/WebGL2 limits, `spec/glspec33.txt`).

## What changed

**Viewport larger than the bound target (task 1).** Wire relaxation (ABI §13.4): VIEWPORT may extend past the
attachment (|x|,|y| <= 32768, 0 < w,h <= 32768); GL semantics, rasterization clipped to the attachment.
- WebGL 2: unchanged (it already applies the viewport as a vertex transform over the whole attachment and discards
  outside the original clip planes), only the validator used to reject it.
- WebGPU (`bgt/renderers/webgpu/view.ts`): the native viewport is clamped to the attachment and a per-draw clip-space
  transform `x' = x*sx + w*ox, y' = y*sy + w*oy` maps the clip volume onto the clamped rectangle exactly where the
  unclamped viewport puts it (window coordinates, coverage, interpolation and `@builtin(position)` unchanged; depth
  untouched). The transform is a renderer-internal uniform (group 2, dynamic offset into a 64 KiB ring, offset 0 =
  identity, a slot per distinct transform); the WGSL epilogue skips it for the identity, so fitting viewports render
  bit-identically. A viewport that misses the attachment skips rasterization (transform feedback still captures).
  WGSL (non-GLSL) pipelines with an off-target viewport are E_IO (documented).
- Profile: no more GL_INVALID_VALUE; glViewport clamps width/height to GL_MAX_VIEWPORT_DIMS (now 16384, was 4096) as
  GL 3.3 §2.13.1 specifies (queries return the clamped size and the unclamped origin); the wire origin is clamped to
  +-32768 (exact for every viewport that can touch a target <= 16384); an empty viewport is a 1x1 rectangle at
  (-32768, -32768).
- Scissor: independent of the viewport on both backends (fixture: scissor inside an off-target viewport).
- **glDepthRange interplay:** n > f is legal in GL 3.3 (was GL_INVALID_VALUE). Sent as (f, n) (§13 needs min <= max;
  WebGL also rejects n > f) with a z flip in the profile's vertex epilogue (meta.y), so window depth (and
  gl_FragCoord.z, depth testing) is GL's `(f-n)/2 zd + (n+f)/2`. Combined with an off-target viewport: checked.

**Provoking vertex (coordinator item 1).** ABI: GLSL flat varyings take the **last** vertex (GL default) on both
backends. WebGL 2 is native. WebGPU (`provoking.ts`): pipelines whose fragment stage has flat inputs draw lines and
triangles last-vertex-first (triangles rotated cyclically, winding kept; lines swapped): non-indexed lists through a
static rotated index sequence with `base_vertex = first` (no per-draw upload), indexed lists through a rotated copy
cached per buffer contents version (64 entries), strips inside the existing strip expansion. Transform feedback
capture runs on the original draw, so captured order is unchanged. glProvokingVertex (was a stub) is implemented:
GL_FIRST_VERTEX_CONVENTION expands draws of programs with flat inputs into lists with each primitive's
first-convention provoking vertex (GL 3.3 Table 2.14: fan i+1, strip i, odd strip/strip-adjacency triangles their
second vertex) last; GL_PROVOKING_VERTEX query. A rasterizing transform-feedback draw under FIRST keeps the last
vertex (counted approximation; feedback order must stay GL's).

**GL_UNSIGNED_BYTE indices (item 2).** Were GL_INVALID_ENUM; widened on the host into the K61 expansion ring (u32
list in the draw's own batched list), any mode, restart index <= 0xff honoured.

**Limits (task 2, item 3).** Table and checker in `tests/support/gl33-limits.ts`; fixture dump of all 58 GL 3.3
implementation-dependent values. Changes:
- Raised to the GL minimum (profile state only): MAX_UNIFORM_BUFFER_BINDINGS 8 -> 36, MAX_COMBINED_TEXTURE_IMAGE_UNITS
  8 -> 48 (binding points / glActiveTexture units; a program still maps <= 7 blocks and 8 samplers onto §13 slots).
- Added: SUBPIXEL_BITS 4, MAX_COMBINED_VERTEX/FRAGMENT_UNIFORM_COMPONENTS (2 x block size), MAX_TEXTURE_BUFFER_SIZE 0,
  MAX_SAMPLE_MASK_WORDS 0, MIN/MAX_PROGRAM_TEXEL_OFFSET 0/0, PROVOKING_VERTEX.
- Honest instead of fake: MAX_CUBE_MAP_TEXTURE_SIZE / MAX_RECTANGLE_TEXTURE_SIZE 4096 -> 0 (targets not implemented).
- Varyings, device-derived through a new §13.6 offset 76 `max_varying_components` (was reserved 0): WebGPU packs the
  linked GLSL varyings into vec4 locations (three classes: perspective f32, linear f32, flat as u32 bits; a varying
  may span locations; values unchanged) and requests the adapter's maxInterStageShaderVariables (M4: 28 instead of the
  default 16), capacity 4 x locations - 6 (worst case of the three classes); WebGL 2 3 x (MAX_VARYING_VECTORS - 1).
  MAX_VARYING_COMPONENTS = capacity, MAX_VERTEX_OUTPUT_COMPONENTS / MAX_FRAGMENT_INPUT_COMPONENTS = capacity + 4. The
  profile now fails a link above it with a `GL_MAX_VARYING_COMPONENTS` info log (before: link succeeded and WebGPU
  pipeline creation failed for > 16 varyings, which the old fixed 60 promised).
- Documented exceptions (exact values asserted): MAX_TEXTURE_LOD_BIAS 0 (2), cube/rect 0 (1024), compressed formats 0
  (4), buffer textures 0 (65536), uniform blocks per stage/combined 7 (12/36: §13 has 8 uniform slots), texture image
  units per stage 8 (16: 8 §13 texture slots), MAX_FRAGMENT_INPUT_COMPONENTS capacity+4 (128), texel offsets 0/0
  (-8/7), samples/sample-mask 0 (1/4), draw buffers/colour attachments 4 (8: §13 4 attachments), dual-source 0 (1),
  geometry-shader limits GL_INVALID_ENUM (no geometry stage). MAX_VARYING_COMPONENTS < 60 only on an adapter with 16
  inter-stage locations (58).

**Found and fixed on the way:** a GLSL identifier equal to a WGSL type name (`f32`, `vec4f`, `mat3x3f`, `array`, ...)
produced a cyclic WGSL declaration (`var<private> f32: f32`) and a compile error on WebGPU; such names are renamed
like WGSL keywords. Linked varying locations above 15 were rejected by the WebGPU frontend even where the device (or
the capture lowering) has more.

## Coordinator decisions needed

1. **Wire relaxation vs profile transform** (K61 decision 3): chose the wire relaxation (WebGL2 stays native; WebGPU
   compensates). WGSL-authored pipelines on WebGPU with an off-target viewport fail E_IO rather than being wrapped.
2. **Reported varying limit is per backend** (106 WebGPU / 87 WebGL2 on M4): a guest querying it sees different values
   on the two backends of one machine, as with K51's uniform block size.
3. **Requesting adapter limits at device creation** (maxInterStageShaderVariables only): no observed cost; other
   limits (uniform buffers per stage, colour bytes per sample) would follow the same pattern if the slot counts grow.
4. **MAX_VIEWPORT_DIMS 16384** is a kit constant (both backends implement the viewport in shader math, independent of
   the device), not a device query.
