## What changed

**GL profile (`platforms/win32/w32_gl.c`, `w32_gl_draw.h`, `_buffer.h`, `_tex.h`, `_query.h`).**
GPU-only lists whose acceptance changes no profile bookkeeping (pass/draw/clear lists without transform
feedback, BUFFER_UPDATE, TEXTURE_UPDATE[_EX]) are appended to one pending continuation list
(`submit_deferred`), with upload bytes copied into a batch-owned 1 MiB arena at the GL call, so later guest
writes to the same client memory cannot leak into an earlier upload. The list is submitted, in unchanged
stream order, before any synchronous submission (creates, deletes, copies, readbacks, requests, feedback
draws, padded-UBO cleanup), at every host yield (`wait_host`: SwapBuffers, transport waits, update end), in
`w32_render`, before GDI record flushes, at glGetError/glFlush/glFinish, and before any newly latched guest
error (so first-error order holds). Size bounds: 256 KiB of commands, 4096 commands, 1 MiB upload bytes.
A rejected deferred list latches GL_OUT_OF_MEMORY for E_LIMIT, otherwise GL_INVALID_OPERATION, at the flush.
Only list boundaries move; `Frame.items` and upload bytes are identical (300-frame trace evidence above).
Native 64-bit test hosts and the `BGT_GL_SYNC_SUBMIT=1` build keep per-call submission.
Metrics: `gl_batched_lists`, `gl_batch_flushes`, `gl_sync_submits`, `gl_batch_replays`.

**Exact acceptance under rejection (new this session).** The ABI rejects a whole list with no effects, so
the previous shape turned one rejected call into a rejected frame (all earlier batched draws lost) and left
profile shadows holding bytes the GPU never received. `tests/e2e/gl-materialization-failure.spec.ts`
(host-injected upload/wire budget exhaustion) failed on both backends with the batched build and passed with
`BGT_GL_SYNC_SUBMIT=1`. Now each deferred call has a journal record (byte range in the pending list, and for
buffer uploads the pre-call shadow bytes and generation, kept in the arena). A rejected batch is replayed as
its original per-call lists in order: each call is accepted/rejected as unbatched, the first rejection
latches the GL error, a draw whose deferred uniform upload was rejected is not emitted (also when the draw
itself goes synchronous, e.g. transform feedback), and shadow bytes are rebuilt (all buffer records undone
newest-first, accepted ones re-applied oldest-first, so overlapping updates resolve exactly); rejected
uniform uploads re-mark the program dirty. Equal-size glBufferData now rewrites the store in place while
deferred (journaled) instead of swapping pointers. Remaining divergence, only under GL_OUT_OF_MEMORY (GL
state undefined): a rejected equal-size glBufferData keeps its old store rather than running the unbatched
delete/create fallback. The spec now passes on both backends and both modes.

**WebGPU (`bgt/renderers/webgpu/gpu.ts`, `webgpu.ts`).** One command encoder spans the frame's §13 passes.
A non-screen native pass outlives its logical PASS_END; the next PASS_BEGIN on identical attachments whose
loads are all LOAD continues it with the §13.1 begin-state reset (viewport, scissor, stencil ref, blend
constant). Screen passes end natively (opaque-alpha store). A BUFFER_UPDATE to a CPU-authoritative buffer
the pending encoder references is renamed (copy-on-write into a pooled native buffer, ≤256 KiB per buffer,
≤4 MiB per frame); GPU-generated or larger buffers split the encoder instead. The encoder is submitted before
blit/copy/readback/mip generation/referenced texture uploads/legacy 2D items. **New this session:**
presentation and the retained-snapshot copy are encoded into the frame's last command buffer (the §13
encoder, or the open 2D pass's encoder), using a dedicated present uniform, so a batched GL frame costs
**one** GPUQueue.submit (was 3: frame encoder, present, snapshot copy). Deletions are deferred until after
the submit of any encoder that used the resource (`retire`).

**WebGL 2 (`bgt/renderers/webgl2/gpu.ts`, `webgl2.ts`).** A non-screen pass leaves its framebuffer bound; a
following PASS_BEGIN on the same native images skips attachment/completeness work. **New this session:** a
GL state shadow for program, VAO, viewport, scissor test/rect, depth range and blend color skips identical
calls across passes and pipelines (359/frame here); the pass disables scissor only when it clears or LOAD-
blits the screen. The shadow is valid only while the §13 pass/draw path is the last GL writer: every other op
(blits, mips, creates, feedback setup, any throw), the renderer's 2D path, frame start and context restore
clear it. It is off for `?gpubatch=0`.

**Timing/census (opt-in, `?gputiming=1`).** WebGPU: `timestamp-query` begin/end pairs per native pass,
resolved after the frame and read asynchronously (reported a few frames late; Chromium quantizes to 100 µs
unless WebGPU developer features are on; the measurement enabled them). The resolve is one extra submit
through the uncounted raw queue entry, only while timing is on. WebGL 2: `EXT_disjoint_timer_query_webgl2`
TIME_ELAPSED around drawFrame, discarded on GPU_DISJOINT; otherwise `unavailable`. `diagnostics.lastFrame`
adds `nativePasses`, `nativeSubmits` (every GPUQueue.submit after device init), `mergedPasses`,
`bufferRenames`, `skippedBinds`, `gpuMs`, `gpuTiming`. A/B switches: `?gpubatch=0` (renderer) and the
`BGT_GL_SYNC_SUBMIT=1` build (profile). ABI §13.12 documents all of this (no wire, opcode, capability or
limit change).

## Findings

- WebGPU: most of the CPU win is renderer-side (asyncify/JSPI: before 1.568/1.534, C-only 1.573/1.463,
  renderer-only 1.300/1.191, both 1.102/1.080 ms); removing 126 wasm→JS submits alone is worth ≤0.07 ms.
  GPU time falls 6–9× because 39 pass load/store round trips disappear.
- WebGL 2 on SwiftShader: a sampled CDP profile (`first/`) puts ~1.9 ms/frame of ~4.5 ms in the single
  production frame-end `getError` (`checkNativeError`, a synchronous GPU-process round trip) and ~2 ms in
  `(program)`; batching cannot remove either. See decision 1.
- An ad-hoc WebGL 2 run on new-headless Chromium with `--use-angle=metal` (real M4) ran at ~750 ms/frame for
  the one config that completed its CPU phase; stopped (disk pressure) and not investigated. No real-GPU
  WebGL 2 numbers in this lane.

## Review vK53 fixes (after `5c8a523`)

1. **MEDIUM, WebGPU pixels.** After a transform-feedback draw the native pass resumes in a fresh encoder
   (`used.clear()`); the rebound index buffer was not re-marked as used, so a later same-frame BUFFER_UPDATE
   of the indices skipped the copy-on-write rename and the recorded drawIndexed read the new indices. Fixed
   (`bgt/renderers/webgpu/gpu.ts`, resume path; the other bindings are re-marked by the draw's own `bind()`,
   attachments by `beginNative`). New `tests/e2e/gpu-feedback-index-rename.spec.ts` (TF on, rasterizer
   discard off, drawIndexed, later index update, readback): **fails on merged WebGPU without the fix** (left
   triangle missing), passes with it on both backends and both modes; asserts merged = per-pass and one rename.
2. **LOW.** `api_BufferData` restored its saved error latch after a failed equal-size update, which could wipe
   an error a replay latched for earlier deferred calls during that same send. Now the restore keeps a replay's
   newly latched error (`replay_error`) instead of flushing up front (flushing first split every frame's batch:
   gl-orphan went 1 → 80 submits). Not reachable with the available fault injection (every fallback re-latches
   the same error); fixed by inspection.
3. **LOW.** `pend_dep_seq` leaked when `flush_padded_cleanup` failed inside `submit_deferred_x`; now consumed
   on that exit too. Not reachable with the available fault injection; fixed by inspection.
4. **LOW.** The journal stored an absolute post-call `generated` value; after a rejected whole write, an
   accepted partial write cleared `generated`, so reads used the stale shadow. Records now store the call's
   transition (whole-store write clears; partial keeps). New case in `examples/x64-gl-ranges` (generated store,
   15 bytes of upload headroom: rejected 16-byte write + accepted 4-byte write, then read) asserted by
   `gl-materialization-failure.spec.ts`: **fails with the `5c8a523` profile**, passes now (both backends,
   both modes). `tests/unit/x64-gl-ranges.test.ts` gains the headroom hook; its recording backend cannot
   produce captured bytes, so the new content note joins the existing expected recording-only FAIL, and the
   generated-UBO retirement count is 3 → 4 (one more TF draw).
