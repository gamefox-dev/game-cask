## Retention decision and exactness

Reviewer **#385** allowed bounded eager width specialization first, only with leaner actual WAT, per-width random/edge differential checks including all flags and partial registers, and no fixture regression beyond paired spread in either mode. **#386 retained narrow IMUL only**, rejecting width-specialized ALU (VM-JSPI and flags-Asyncify regressions) and shift flag-liveness (neutral).

The sole production change is platforms/x86/x86_lift64.h: always-inline xl_imul uses signed int64 products for widths 1/2/4; width8 still calls the old signed-i128 recipe, renamed xl_imul_wide. Signed32×signed32 fits in int64, so no new signed multiply overflow. Result truncation/sign extension and full-result comparison preserve exact CF/OF; all other flag bits remain untouched. Register partial writes/32-bit zero extension, checked memory and fault publication, clocks/retirement, direct/indirect calls, callbacks, native admission/resume and suspension are unchanged. tools/x86/lift64.h is byte-identical to base. Existing content dependencies invalidate header users naturally; no cache-key shortcut.

Only original executable wasm operators count: instrumentation, block/loop markers, synthetic exits and overlapping EA slices are excluded. Counted modules are never timed.
