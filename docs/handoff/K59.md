## Q2: pack `net::ERR_ABORTED` after full delivery

* `captureEngineErrors(page, files, { build })` (build dir or manifest) also tracks every `*.pck` and the wasm with the
  manifest's SHA-256 **and byte length** (`buildAssets`); `{ assets }` adds others. Classification is one pure
  function, `classifyCancellation`: ERR_ABORTED is `canceled-after-complete` only with HTTP 200, EOF at cancellation
  and at the end, Content-Length = received = manifest length, and the pinned hash. Partial, wrong-hash, wrong-length,
  unsized (no Content-Length) and never-fetched tracked bodies fail.
* Large bodies are copied once into a buffer preallocated from Content-Length (was: chunk copies + concatenation, 2x).
* Used by engine:probe, the port smoke template, godot-runtimes.spec (all 6 runtimes now assert the pack body).
* I could not reproduce Chromium's late abort deterministically (a GC-race between body EOF and loader completion;
  tried Godot's exact wrapper + forced GC, 0/20). The rule is unit-tested on the pure function; the browser tests
  prove the pack evidence is recorded and that every failing mode fails.

## Q5: recorded engine error allowlist

`engineProfile.allowedErrors: [{ message | pattern, justification, evidence }]` (≤32). `message` must be an
`ERROR:`/`USER ERROR:`/`SCRIPT ERROR:` line; `pattern` is whole-line, must start with the literal prefix, ≥24 literal
characters, and is refused if it matches '' or generic engine errors (sentinel lines). Justification 20–1000 chars;
evidence is a relative path that must exist at build time (SHA-256 into the manifest; ids E1…). In the adapter only
ERROR-prefixed lines can match (an entry for `Aborted(...)` matches nothing); the matched line and its indented `at:`
continuations are logged as warnings and counted. `diagnostics().allowlisted`, probe.json `allowlisted` and the build
report list every entry with `count`/`continuations`, zero included. Real 3.5.3 test: the CC0 duplicate-signal script
fails without the entry and passes with it (count 1, continuations 1).

## Q7: engine options + frame pacer (coordinator addendum)

* `engineProfile.engineArgs`: Godot 3/4 allowlist `--fixed-fps 1..1000`, `--time-scale 0.01..100`,
  `--frame-delay 0..100`, `--print-fps`, each once; the build also refuses an option whose NUL-terminated literal is
  absent from the exact runtime's wasm (all four are present in all 6 pinned runtimes). Passed through the Engine
  config `args`; manifest + shell identity carry them; build report prints `engine args: …`. 3.2 legacy shell: refused.
* `tools/engine/pacer.mjs` (test/probe only): virtual `requestAnimationFrame`; one engine frame per real frame on
  `step(n)`; `inputAt(frame, events)`; `frameHash(n)` hashes the canvas in the same task as the last engine frame.
  `engine:probe --pace FPS` exposes `p.inputAt/p.frameHash/p.engineFrame`; probe.json `pacer`, `engineArgs`, notes when
  `--fixed-fps` is missing/different. The adapter and perf helpers use the real rAF; `openEngineProfile` and the
  engine branch of the probe facade poll on an interval (Playwright's default rAF polling would hang).
* CC0 physics fixture (jumping box, `print("state <frame> x y")`): with `--fixed-fps 60` three runs (one with wall-time
  jitter) give identical frame-indexed states and 4 distinct identical screen hashes; a jump one frame later differs;
  without `--fixed-fps` the jittered run drifts (more physics steps). The pacer freezes the engine between steps, and
  drives Godot 4.3 (both variants) and 4.4.1 reproducibly.
