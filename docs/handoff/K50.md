## Approved contract and implementation

Reviewer #475/#476 approved timing/ABI decisions before implementation:

- Existing 2M dispatch-unit quanta rotate threads, not host updates. Fixed nominal **4000 units/us**,
  including REP budget units, progresses busy-wait clocks without wall-time or optional counter inputs.
  Sync partial per-thread debt at scheduler boundaries; clock reads include live debt. QPC is 1 MHz.
- Successful interval-N positive swap snaps forward to the 16667-us grid, at least N periods since
  the preceding present and never backward. Interval 0 does not snap. CPU/idle elapsed time is credited.
- Default process cap **64M**, configurable `pipeline.timeModel.instructionCap` **2M..256M**;
  manifest records version 1, cap, rate and period. Short rotations cannot evade cap checks.
  Maximum cap overshoot is a quantum. Non-presenting guests and infinite idle waits remain bounded.
- All-idle scheduler jumps to earliest finite thread/audio/USER deadline, clipped to the next clock
  frame. Transport file/range/readback waits add no virtual time merely because the host is slow.
- Dirty GDI batches count once at USER/cap/idle boundaries. Follow-up reviewer approval adds dirty-only
  Sleep(0)/SwitchToThread boundaries; clean zero sleeps remain zero-time rotations. The recorder flushes
  bounded overflow through transport only (no clock frame/present), restoring draw state afterward.
  Eight 1-MiB records keep even sprite-only batches below the BGT per-frame vertex limit.
- Additive optional read-only `bgt_guest_time_us()` export feeds deterministic time/audio. Simulated
  audio drains by guest clock, retaining its last-drain timestamp in savestates. Native BGT fallback
  remains completed updates × 16667 us. Clock/debt/cap state is wasm state on both oracle sides.
- `step(n)` remains n consumed host updates, not quanta or guaranteed presents. Pipeline page loop
  runs at most one update per rAF, carrying at most one period of remainder and dropping older backlog;
  native BGT catch-up is unchanged. **Fix (c057fc4, from K51's finding):** the first K50 loop zeroed the
  accumulator after every update, so a 60 Hz rAF (ticks ~16.66 ms < 16.667) updated only every other
  tick (K51 measured 34 presents/s on x64-smoke). `bgt/runtime/page-pacing.ts` `retainedAccumulator`
  is equivalent to K51 6025fea's `page-fps.ts` function (same name/semantics; keep one at integration);
  `tests/unit/page-pacing.test.ts` simulates jittered 60 Hz ticks (old <0.55, new >0.99 updates/tick). Deterministic
  cap is not hard wall-ms preemption. Existing suspended-JSPI snapshot rejection is unchanged.
