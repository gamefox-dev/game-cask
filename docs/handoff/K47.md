## Changes and semantics

- DEV / VITE_BGT_TEST install the test API but no longer force strict renderer queries. Only explicit
  ?debug=1 selects strict behavior. Diagnostics expose nativeQueryPolicy (production / strict / null on
  WebGPU), aggregate nativeSyncQueries and per-op nativeSyncQueryOps, including frameEnd.
- Win32 glBufferData on a live **equal-size** store submits one full BUFFER_UPDATE instead of DELETE + CREATE.
  It retains exact guest/native logical size, not spare capacity. Growth/shrink retain delete/create.
  New shadow, mapping reset (including map access), and generated-state reset commit only after synchronous
  submission acceptance. A rejected UPDATE restores the prior first-error latch, then runs the old
  DELETE/CREATE path unchanged: rejected DELETE retains the old state; accepted DELETE plus rejected CREATE
  clears size/mapping/generated state; successful fallback replaces the store without the speculative error. NULL data retains the existing deterministic zero fill. TF-bound active-buffer rejection still
  precedes uploads. The transport owns upload bytes in stream order; earlier draws see earlier contents on both
  backends. No wire ABI or capability gate changed.
- Cumulative successful live-store counters: gl_buffer_respec_reused, gl_buffer_respec_resized,
  gl_buffer_respec_grew, gl_buffer_respec_shrank. Initial allocations and failures are not counted.
- No allocation-error deferral, speculative pre-drain removal, FBO-cache rewrite or send coalescing. K46's
  native-storage-generation cache already survives unrelated buffer churn. Keeping synchronous acceptance in
  send preserves guest error timing/order. Reuse alone removes 80 submits/frame in the fixture; speculative
  coalescing was not justified by the small WebGPU runtime CPU delta.

Reviewer approved equal-size-only reuse, no capacity doubling/retention, synchronous checks, commit-after-acceptance
and ordered old/new draw contents. Review #451 found a P1 in initial rejection handling and a P2 per-command
attribution-string allocation. Repaired with failure-only replay of the original delete/create path (restore the
pre-UPDATE error latch first) and precomputed opcode labels. Rejected updates emit no native item or shadow mutation;
a unit test pins this. At the exact kit transport work-budget edge a speculative rejected UPDATE still charges
**40 wire bytes / 1 command / 1 submit** before fallback. Coordinator explicitly accepted this existing bounded-work
accounting (not GL semantics); no ABI/accounting change. A regression pins that charge as well as all three
fallback outcomes, with and without an earlier guest error. Fresh independent vK47b delta review of ee9c915 **PASS** (bridge #455): P1 matched 4951c3b at every
old failure stage with/without prior error; P2 fixed, no new findings. This is independent code/focused validation,
not a claim of independent full Tier 1 execution. The fresh K47c continuation completed the remaining gates
and audited their structured evidence; no implementation changed during that continuation.
