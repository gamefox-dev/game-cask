## Bug

`identifyRunner` set `mono` whenever the runner bytes contained `GodotSharp`, `mono_gd` or `GodotPlugins.dll`.
Every official 3.5.3 build contains `GodotSharp` as a symbol string, including the kit's pinned non-Mono `godot.wasm`.
So a real official, non-Mono 3.5.3 Windows game (signature `3.5.3.stable.official`) was refused with
`Mono/C#, Mono/C#-runner`, and `npm run inspect` recommended lifting instead.

## Fix (tools/engine/godot.mjs)

* **Runner:** Mono is flagged only when a version signature has `.mono.` (`x.y[.z].<status>.mono.<build>`).
* **Companion files / pack paths** (`MONO_PATHS`, checked on the pack directory and the inspect inventory):
  `GodotSharp.dll`, `GodotPlugins.dll`, `GodotTools*.dll`, `mono-2.0-sgen.dll`, `MonoPosixHelper.dll`;
  `data_<name>/Assemblies|Mono/`; any `.dll` inside a `data_*` folder (Godot 4 .NET `data_<name>_<platform>_<arch>/`);
  `.mono/`, `godotsharp/`, `mono_gd*/` directories; `.cs/.csproj/.sln`. CLR assemblies (`pe-dotnet`) and the
  `C#` feature / assembly-name settings stay as before.
* **New pack-resource evidence:** a text resource referencing `path="res://….cs"` (a C# script) → `Mono/C#`.
* **Tightened detectors that matched official or innocent content:**
  - A plain `mono/` folder (e.g. mono audio) is no longer Mono evidence (only `.mono/` and the data layouts are).
  - Mono assemblies are classified `Mono/C#` only, not also `native-extension/*`.
  - Godot 4 official Windows export DLLs (`D3D12Core.dll`, `d3d12SDKLayers.dll`, `dxil.dll`, `libEGL.dll`,
    `libGLESv2.dll`) are not GDExtensions. Other `.dll/.so/.dylib` files still block (e.g. `steam_api64.dll`).
  - `export_presets.cfg` (editor metadata that older 3.x exports ship; never read at runtime) is not text-scanned,
    so its `export_path="….pck"` no longer reports `additional-packs`.
  - Threads, OS.execute, GDNative/GDExtension text and encryption detectors only scan game resources or check
    structure (GDEC magic, pack flags). None of them matches strings in the official runtimes, so they are unchanged.

## Tests

* Fixture writers: `makeRunner(..., { mono: true })` (Godot 3 and Godot 4) writes `<version>.stable.mono.official`.
* tests/unit/engine-godot.test.ts "K58": a non-Mono runner containing `GodotSharp`/`mono_gd`/`GodotPlugins.dll` gets no
  blocker and the engine path is recommended. A `.mono.` signature, companion DLLs, data folders, `.mono/` assemblies
  in the pack and `.cs` script references give exactly `Mono/C#`. Official Godot 4 export DLLs, `sfx/mono/` and
  `export_presets.cfg` give no blocker, and a real native library still does. A provisioned-runtime check runs
  `identifyRunner` over each cached official `.wasm/.js` (`it.runIf` provisioned; it is skipped on machines without a
  runtime cache).
* **Contract change:** tests/unit/engine-profile.test.ts used to assert the false positive
  (`makeRunner('GodotSharp PThread')` → `Mono/C#-runner`). It now expects `[]`, and a `mono: true` runner expects
  `Mono/C#-runner`.
