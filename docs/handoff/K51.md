# K51 — measurement validity before more speed work

Branch `lane/K51`, base `9d8fee8` (in-progress K50 head). This is kit development only. I used only CC0 and
source-built fixtures: no game files, no network, no installs, no pushes. The scratch directory is
`/Users/dev/projects/pi-work/scratch-K51`, and `BGT_E2E_PORT=5304`. Raw numbers are in
[K51-measurements.json](K51-measurements.json). The user guide is [performance.md](../performance.md).

## 1. Real-GPU WebGL2 and honest uniform limits

- **Probe evidence** (this machine, Playwright Chromium):
  - headless shell default: SwiftShader, `MAX_UNIFORM_BLOCK_SIZE` 65536, alignment 256.
  - `--use-angle=metal` or `channel: chromium`: ANGLE Metal, Apple M4, `MAX_UNIFORM_BLOCK_SIZE` 16384,
    `MAX_VERTEX_UNIFORM_COMPONENTS` 4096, alignment 16, 32 bindings.
  - Every other gate passes on Metal. Only the 65536 requirement refused CAP_GPU.
- **Gate:** `WebGL2Gpu` now requires 16384, the WebGL2/GL 3.3 minimum. Its `maxUniformRange` is min(65536,
  the native value rounded down to 16). `WebGPUCommands` takes `maxUniformBufferBindingSize` (65536 by
  default). WebGPU has no capability gate, so nothing on that side was too strict. It requests default limits,
  and those meet every BGT ceiling.
- **Host and ABI:** `GpuState.uniformRange` (`backendUniformRange`) rejects a backend below 16384 and clamps
  to [16384, 65536]. §13.6 offset 52 reports this value; it stays 65536 without CAP_GPU. `UNIFORM_BUFFER`
  sizes above it return `E_LIMIT`. Both renderers refuse to bind a larger native range. They also refuse a
  restored device that reports less than the advertised value. ABI.md §13.4/§13.6 and the desktop
  uniform-block paragraph are updated.
- **GL profile:** `GL_MAX_UNIFORM_BLOCK_SIZE` returns the live §13.6 value; it is queried at link and at
  `glGet`. A std140 block, or the profile's own default-uniform block (meta + uniforms + swizzles), above the
  limit fails compile/link with an explicit `GL_MAX_UNIFORM_BLOCK_SIZE` log. An oversized `glBindBufferRange`
  stays legal GL: there is no error, and the draw binds the linked block size.
- **Diagnostics:** `gpuDevice` holds the renderer, `software`, the native and reported limits, and the
  languages. It is captured once at init, not per frame.
- **Tests:**
  - native `gl-frontend-memory uniform-limits`: 16384 and 65536 for GetIntegerv, the std140 block and the
    default block.
  - units `gpu-limits` and `gpu-commands`: offset 52 and the validator at 16384, 16390, 65536 and 1 MiB;
    a backend below 16384 is rejected.
  - new CC0 fixture `examples/x64-gl-limits` with unit `x64-gl-limits`: limits 16384, 32768 and 65536; the
    UNIFORM_BUFFER size equals the limit; exactly one pipeline.
  - e2e `gpu-uniform-limits.spec.ts`: the guest limit equals the device limit, and the at-limit block draws
    magenta.
  - With `BGT_WEBGL2_GPU=1`, the e2e spec asserts the renderer is not software. An injected 16384 keeps
    CAP_GPU; 16368 clears it.
  - Passes on WebGL2 SwiftShader, WebGL2 Metal and WebGPU.
- **Infrastructure:** `BGT_WEBGL2_GPU=1` puts the `chromium-webgl2` project on the native GPU; it is opt-in.
  `npm run probe` and `npm run bench:page` now use the native GPU for WebGL2 by default, and `--software`
  gives SwiftShader for A/B.

## 2. Real-page fps

- **API:** `__BGT_TEST__.measurePage(windowMs, warmupMs)` and the CLI `npm run bench:page`
  (`tools/bench/page-fps.mjs`). Details are in performance.md.
- **What it measures:** the page's own rAF loop runs. The runtime keeps a bounded log of ticks, busy ticks
  and completed canvas presents. The guest present delta comes from the native present counter.
- **Output:** a JSON summary for each backend and mode, with the renderer string and machine resources.
- **Finding (fixed):**
  - The K50 pipeline loop set `acc = 0` after its single update.
  - A 60 Hz rAF gives ticks of about 16.66 ms, just under the 16.667 ms step, so updates happened only every
    other tick: 34 presents/s on both backends and modes.
  - `retainedAccumulator` now keeps up to one step of remainder, so a stall still drops its backlog. The
    result is 60 presents/s. Native BGT catch-up is unchanged.
  - Unit `page-fps` has a pacing simulation that fails on the old policy.
- **Caveat:** these are headless rAF numbers at 60.0 ticks/s. x64-smoke is light and vsync-bound; it shows
  pacing, not engine throughput. SwiftShader WebGL2 also reaches 59.5–59.7. Use `--headed` for numbers paced
  by the display.

## 3. Performance build without coverage

- **Build switches:** `BGT_COVERAGE=off`, `build.mjs --no-coverage` and `npm run build:port -- --no-coverage`
  all select `X86_COVERAGE_MODE=3`.
- **What is compiled out:** the generated `x86_coverage_lifted` hooks, the runtime interpreter-entry hook and
  the interpreter coverage rows. The wasm no longer imports `coverage_entry`.
- **What it reports:**
  - metrics give `coverage_mode: 3` with null counters;
  - the manifest has `pipeline.instrumentation` (coverage, cpuProfile, accounting, dispatchCounters,
    ownerCensus);
  - coverage snapshots carry `recording: "off"`, and slice packaging rejects them.
- **Refused combinations:** `--slice` and `BGT_COVERAGE_DIRECT=1`.
- **Test:** unit `coverage-off` on x64-basics (AMD64) and win32-hello (i386), both modes, 300 frames. It
  checks the missing import, the flags, the manifest, the null counters, and API traces identical to the
  normal build and to the interpreted oracle.
- **Speed:** −26% wall time on the 16M-call loop.

## 4. Owner census

- **Switch:** `BGT_OWNER_CENSUS=1`. It implies exact accounting and is refused with `BGT_CPU_ACCOUNTING=0`.
- **Lifted code:** both lifters emit `XR_OWNER(owner)` once per i386 function or AMD64 region, and commit
  through `XR_LIFT`.
- **Generic and interpreted code:** attributed by the owner range of the instruction address; code outside
  every range goes to `unowned`.
- **Storage:** 16384 rows. Overflow is counted as `unattributed`.
- **Output:** a cumulative top-32 table plus an 8-frame ring of per-present top-32 tables, as decimal
  strings, plus a numeric `execution_summary.owner_census`. OFF builds report enabled:0 and null tables.
- **Zero cost when OFF:** the default-build wasm sha256 is identical with and without the K51 lifter changes
  (calls fixture, direct and indirect).
- **Test:** unit `owner-census`:
  - hand-counted entry/a/b owners, i386 and AMD64, lifted and interpreted, both modes; the AMD64 CPUID shows
    up as generic under b;
  - per-present totals equal the exact accounting deltas on the x64-gl-limits SwapBuffers loop;
  - two fresh runs produce identical tables.

## Review vK51 fixes (after 6025fea)

1. **Default-uniform budget.** The profile's meta and swizzle words no longer count against the guest's
   default-uniform budget. When they would not fit beside the uniforms, `gp_link` relinks with a split
   layout: `bgt_u0` holds only the ordinary uniforms, and meta plus swizzles go to `bgt_u<nb+1>` at a
   256-aligned offset in the same buffer. Draw binds both blocks and adds the slot to the pipeline uniform
   mask. The inline layout, and the stream it produces, is unchanged whenever everything fits. With all 7 user
   blocks in use there is no free slot, and the program keeps the single block.
   - The native `uniform-limits` case now expects `vec4 u[1023]`+sampler and `vec4 u[1024]` to link on a
     16384 device; it checks the split layout fields.
   - `u[1025]` still fails.
   - `x64-gl-limits` gains a 1024-vec4 default-block program drawn cyan on the left half. Unit: the slot-0
     binding is 16384 bytes and the meta binding is slot 1, offset 16384. e2e: native pixel check.
2. **WebGPU guard.** `WebGPUCommands` refuses a `UNIFORM_BUFFER` range above `maxUniformRange` (new
   gpu-pipeline-lifetime test).
3. **JSPI browser failures fixed in the harness.** The JSPI preflight in `fixtures.ts` navigates to
   manifest.json, so full Chromium requested `/favicon.ico` and the dev server returned 404. The harness now
   answers `**/favicon.ico` with 204; no real request or error is allowlisted. A standalone Chromium check
   reproduced the 404 without the route and showed no error with it.
4. **Page-loop log.** It is allocated only while `measurePage` runs (null otherwise). Overlapping
   measurements are refused.
5. **Software-renderer check.** `npm run probe` throws, and `bench:page` marks the run skipped, when a
   native-GPU WebGL2 run gets a software renderer without `--software`. probe.json records `device` and
   `software`.
6. **Docs corrected.**
   - WebGPU→WebGL2 fallback without live resources: it renegotiates a new namespace, possibly with
     16384, and programs linked afterwards use it.
   - Census: 16384 slots at 3/4 load means 12288 attributable owners; the rest is `unattributed`.
