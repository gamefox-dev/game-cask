# K12 — efficient deterministic guest heap

## Delivery and boundaries

Based on `d4c30dc`, branch `lane/K12`. Engine-independent Win32/CRT guest allocation; no wire ABI changes,
renderer changes, dependencies, game inputs, captured shader/source copies, system installs, web access or push.
All new fixture/benchmark sources are original CC0-1.0. The separate host-libc allocator is unchanged.

- `platforms/win32/w32_heap.h`: two-level segregated free lists (16 sub-bins/power of two), bitmap selection,
  four fixed offset subcategories per bin, 32-byte boundary tags, eager two-sided coalescing, split shrink,
  next-free in-place growth, deterministic move/copy and requested-size tracking. Allocation/free metadata
  work is O(1) in live-block count, with at most two bitmap lookups; virtual-reservation lookup is bounded
  by 256 entries. Copy/zero/map work remains O(bytes/pages), never claimed constant-time.
- `w32_core.c`: preserves on-demand mapping, virtual reservation barriers and high-water metrics. No heap
  scan from W32_HEAP_LO. Released reservations remain skipped instead of interpreting stale bytes as tags.
- `w32_kernel.c`: real logical separate heaps, ownership, flags, errors and live-footprint quotas. 255
  simultaneous private heaps; reclaimed slots use generation-tagged handles and retire before wrap.
- `w32_crt_alloc.h`: shared both-width malloc/calloc/realloc/free/_msize/_recalloc and full aligned/offset
  allocation, size, realloc/recalloc/free families. Checked products/full-width sizes, requested sizes,
  zero-new-tail semantics, EINVAL/ENOMEM and failure preservation. The common CRT registry is now 434
  function names plus ten data names; i386 gains the allocation families through its existing kernel table.
- `w32_x64.c`: STATUS_NO_MEMORY through existing SEH, with exception records/filter pointers in reusable
  misc-arena scratch so real heap exhaustion cannot prevent filter dispatch. i386 reports its unavailable
  general SEH dispatcher precisely. Nested SEH/native callback failure is explicit, not a sentinel crash.

Full contracts and limits: `platforms/win32/CONTRACTS.md#guest-heaps-and-crt-allocation-k12`.
Reviewer accepted a shared backing arena with **separate logical ownership**, `initialSize` as a validated
hint (no upfront commit/reserve), and maxima counting aligned **live footprints including headers**, not
native Windows reservation parity. These limitations are not fabricated native compatibility claims.
HeapValidate/HeapWalk/HeapCompact were absent and remain unregistered, not success stubs.

## Regression evidence

`x64-heap` and `x86-heap` are ordinary PE pipeline fixtures, with Windows imports/dynamic CRT calls, no
BGT imports or overrides. They check payload bytes, requested sizes, alignment, zero allocation/shrink/
regrowth/move, next-free growth/in-place-only refusal, coalescing, fragmentation, separate heaps and stale
handles, tight maxima, destruction, all flags, last error and errno, all aligned/offset families, overflow
and virtual-reservation sentinels. A 12,000-allocation workload grows/interleaves realloc/free. Both modes
have exact-address API-trace oracles at 300 frames. Both browser backends require the completion summary,
no failure logs, no runtime/command errors, no stubs/interpretation and a changing API trace.

`tests/unit/heap.test.ts` additionally builds original failure-only guests for HeapAlloc/ReAlloc/Create
exception flags, both widths and execution modes; an AMD64 128 MiB-window probe genuinely exhausts heap
backing down to the minimum allocation, then catches STATUS_NO_MEMORY and verifies original content and
cleanup. A distinct nested-filter probe requires the explicit unsupported-continuation failure.
`tests/native/heap_driver.c` compiles the actual allocator: 150,000 randomized operations per width,
payload validation, full physical/free-list/ownership/category/bitmap invariants, bounded actual metadata
reads/writes, class boundaries, failed mapping, quotas, generation reuse and reservation-gap barriers.
Persistent GCC lint compiles both width configurations; its cleanup tests cover every compiler failure.

Independent validation ran in **fresh read-only pi sessions**, not a claimed delegated test suite. Initial
review found: heap-dependent OOM filter scratch, tight-quota unsplittable candidates, lifetime heap-slot
exhaustion, and stale HeapCreate OOM last error. Follow-ups found larger-bin and same-partial-bin quota
selection edges. All have fixes and discriminating regressions. Final independent result:
**PASS within accepted source/native scope**, actual strict-warning and ASan/UBSan randomized runs both
widths, 106,832 category/lookup checks per width, genuine exhausted-backing quota regressions, generation
retirement, production gap helpers and 2,324 aligned-offset adapter cases per width. It did not run guest,
browser, oracle or Tier 1 gates. Logs under `/tmp/k12-independent/` are machine-local, not durable promises.

## Same-machine performance evidence

Committed `K12-heap-before.json` / `K12-heap-after.json` include compiler, allocator/workload hashes, per-phase
CPU time, true live counts, extent, checksum, CPU/RAM/load/disk snapshots and child resource statistics.
`node tools/bench/heap-bench.mjs d4c30dc OUTPUT` and `... working OUTPUT` compile the **actual** allocator
against the same native C memory adapter/workload, not host malloc. Mapping is simulated successful; this
isolates allocation metadata/content work, not wasm growth, browser dispatch, rendering or target gameplay.

Original CC0 workload: **250,000 allocations, 216,667 reallocations, 209,995 frees in timed phases**, growing
from **4,005 to 40,005 live allocations**; final frees occur outside phase timing. Both checksums are
**1,249,975,000**, and workload SHA256 matches. On Apple M4/10 CPUs/16 GiB, clang 21 `-O2`:

| Phase/live set | Before ns/operation | After ns/operation | Before ns/allocation, mixed work | After ns/allocation, mixed work |
|---|---:|---:|---:|---:|
| 0 / 4,005 | 3,620.363 | 15.799 | 9,798.44 | 42.76 |
| 4 / 20,005 | 60,822.986 | 12.990 | 164,628.36 | 35.16 |
| 9 / 40,005 | 149,858.129 | 17.497 | 405,618.00 | 47.36 |

The replacement stays in a **12.606–17.497 ns/operation** band across the ten phases rather than growing
with the live set; old first/last ratio 41.4×, new 1.11×. The mixed-work-per-allocation column includes
realloc/free work, not an isolated malloc latency. Final heap extent is **10,198,224 → 11,029,504 bytes**
(+8.15% for tags/classes); native maximum RSS **11,304,960 → 12,746,752 bytes**. Aggregate timed phase CPU
and total wall time are distinct; wall includes scheduling/startup and is not the scaling assertion.
Machine contention is visible in the snapshots. These are bounded allocator measurements, **not** a
claimed target speedup, first draw, title, playability, mobile result or whole-browser performance bound.

## Explicit x86-runtime follow-up (reviewer-accepted boundary)

Reproduction: remove the explicit nested guard in `w32_heap_no_memory`, run the `HEAP_EXHAUST + HEAP_NESTED`
variant of `examples/x64-heap/heap.c` in either execution mode. `heap_filter` invokes `heap_catch` again;
the inner failure dispatches a second SEH exception, selects its landing pad and unwinds native C callback
frames. The resumed guest filter later returns to **0xfffffff0** (`X86_CALLBACK_SENTINEL` in
`platforms/x86/x86_rt.c:x86_callback64`) but its original native caller no longer exists, producing an
invalid guest memory/dispatch access. This is the existing general nested-native-callback/SEH continuation
gap, not an allocator free-list failure. A general fix needs resumable callback continuations coordinated
with nonlocal SEH transfer, saved CPU/nonvolatile/stack state and the scheduler's native-continuation
lifetime; simply resetting X.transfer or pretending a filter returned loses unwinds/state.

Reviewer explicitly directed **no x86-runtime expansion here**. OOM inside an already dispatched SEH/native
callback now aborts with `guest heap STATUS_NO_MEMORY (0xc0000017): nested SEH/native callback continuation
unsupported`. The negative regression tests that diagnostic in lifted and interpreted builds. Ordinary
caught STATUS_NO_MEMORY under completely exhausted backing must and does remain separately tested.
