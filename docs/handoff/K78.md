## 1. Check build (`liftFast.check: "sync"`, task 1)

`tools/x86/lift64_fast.h` (`--fast-check sync`), reporter `xf_sync_violation` in `platforms/x86/x86_rt.c`
(`x86_sync_check_t` in `x86_guest.h`), metrics `sync_check` in `platforms/win32/w32_core.c`, probe line + `probe.json`
field in `tools/probe/probe.mjs`. Opt-in; with the key absent or `"off"` the generated C is byte-identical (tested).

The check build **executes with the full form's values** and verifies every decision minimal sync and the Win64 call
contract make, so a game that crashes in compact16 because of sync keeps running and names the offending code:

- at every spill (call, tail call, exit, quantum yield, generic instruction, inlined RET mismatch) the registers
  minimal sync leaves clean are compared with `X`; a difference is **kind 1** (dirty-set miss) and is put back;
- after every returned call every used volatile register is reloaded; one minimal sync would not reload and whose
  value the callee changed is tracked in a 16-bit local (`xs`); reading it (by the analysis' own read model) or
  storing it before a write is **kind 2** (liveness miss);
- after every returned call the callee-saved registers the caller uses are compared with `X`: **kind 3**; around every
  inlined call the callee-saved registers the inlined subtree writes are snapshotted and compared at its return
  label (inlined RET and inlined tail call): **kind 4** (the inlined copy exposes a clobber a real call hides, so the
  result depends on `liftFast.inline`);
- at lift time every non-control instruction's emitted C is scanned for `r[N]` reads/writes and compared with the
  register model the analysis uses (`l64f_gpr_reads/writes`); a miss is **kind 5** at run time, a stderr line and
  `fastCheckModelMisses` in the module's lift stats (0 on every fixture here).

Report: every violation counted per kind; the first stored; the first 8 distinct (kind, register, PC) logged as
`x86 sync check: <kind>: register <r> at guest pc 0x.. in guest function 0x.. (lifted N_..), callee 0x.., found 0x..,
full form 0x..`. `guest function` is the inlined callee when the code was inlined into the owner `N_`.
`host.metrics().sync_check` / `diagnostics().metrics.sync_check` = `{violations, dirty_miss, liveness_miss,
callee_saved_clobber, inlined_callee_saved_clobber, register_model_miss, first: {kind, register, pc, function, owner,
callee, found, full_form, kind_code}}`, `null` in other builds. `npm run probe` prints `probe: sync check N
violation(s); first: ...` and stores it in `probe.json` (`sync_check`). EFLAGS are not checked (minimal sync stores
`flags` at every call and exit exactly like the full form; fast mode never computes dead flags, K75 covers the
profile's observers). With `sync: "full"` only kinds 3/4 are checked.

Proof the check works (`tests/unit/fast-check.test.ts`): an ABI-breaking callee (`mov ebx,9; ret`) is kind 3 as a real
call (full and compact; exact message asserted) and kind 4 inlined; `testCorrupt: "sync"` (test-only, refused in
port builds like `"stack"`) drops the highest dirty register from every spill and every volatile reload after calls:
without the check the result differs from the interpreter, with it kinds 1 and 2 are reported and the result equals
the interpreter's; ABI-clean recursion/joins (inline 0/16/48, full and compact, quantum budgets) report nothing.

### Bug 1: minimal sync ignored code reached only through entries

The AMD64 analyzer sweeps a function's whole `.pdata` range, so a function also contains code no static edge from
its start reaches: C++ landing pads and catch continuations, case bodies behind jump tables it cannot recover.
That code runs natively from the fast entries inside it (post-call sites, loop headers) once the slow path has
interpreted up to one. `l64f_flow` propagated dirty registers only from the function start, so writes there were not
stored at the next call or exit of the code it jumps back into. k78-unwind: the catch block of `virtuals()` (inlined
into `main`) sets R14/R13 and jumps back to the loop, whose `call` at 0x01001556 did not store them, so `X` held
stale R14/R13 (the values callees save and the unwinder restores; the mechanism of the wrong output after that was
not traced further: the check build repaired it and the fix removes all 13 reports). Fix: every entry seeds the forward
analysis (synchronized, dirty 0); an inlined copy still starts only at its start. Test (raw code, fails before on
6/6 minimal-sync shapes, inline 0/16/48, sync minimal and compact): `lea rax,[rip+P]; jmp rax` reaches
`P: call k; mov ecx,7; jmp S`, `S: call h` must pass ECX=7. **Q144 relation:** MSVC switch statements whose tables
neither the analyzer nor the fast emitter recovers, and EH continuations, are exactly this shape, and only `sync:
minimal` is affected (calls outlined and names strip alone pass; sync alone was not run). Plausible, not proven:
re-run compact16 on the game.

### Bug 2 (every lift mode): unanalyzed address inside a lifted owner

The registry maps an address to the owner whose range holds it. A function without `.pdata` is walked, not swept,
so the target of a jump table the analyzer cannot recover is not one of its instructions. The fast form interprets
such an address (`slow:`); the exact form (also used in fast mode for functions over 4096 instructions or whose
first listed instruction is not the entry) left through `exit` without progress and the dispatcher faulted
(`lifted AMD64 entry made no progress at 0x01001198`, k78-shapes in exact, fast, inline 16 and sync minimal). Fix
(`tools/x86/lift64.h` landing): a fresh entry at a non-instruction address inside the region's span is interpreted
like any interior entry; internal indirect jumps keep `exit` (their registry dispatch re-enters as a fresh entry).
Test: fails before in the exact form (`made no progress at 0x00002026`), passes in all three modes after.

## vK78 review fixes

Independent review: both lifter fixes sound; two findings in the check build, fixed with tests that fail before:
- **HIGH (kind 4 missed generic writes):** the inline snapshot covered only registers the specialized model writes
  (`l64f_plan`), so an inlined CPUID clobbering RBX gave zero reports. `l64f_plan_generic` walks the same inlining
  decisions; when the subtree holds any generic (helper-emulated) instruction, every used register is snapshotted
  (generic writes go to `X` and the locals reload all used registers after it). Flags are outside the callee-saved
  contract (not checked, section 1); register writes by helpers in specialized code are what kind 5 verifies. Tests:
  inlined CPUID and inlined BSF changing RBX, full sync and compact: kind 4 at the call, 4/4 (0 reports before).
- **MEDIUM (kind 3 blamed later callees):** a callee-saved register the caller only reads is never stored by any
  form, so after one clobber `X` stayed different and every following call was reported. For such registers the
  clobbered value now becomes the reference after a report (`xk`/`xr_N`, reset when a generic instruction reloads
