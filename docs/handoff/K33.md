## Root causes and fixes

1. **Linux E2BIG in scale.** Large child plans, Asyncify removelists, partition/chunk/symbol selections,
   compiler macro sets, and compiler dependency/diagnostic data were being carried through argv, response
   expansion, environment, or unsafe descriptor forms. The transport now stages argv plans in private files
   (fd 3), reconstructs large Node arguments after spawn, uses finite file/stdin transport for lift/compile,
   uses selection files for large symbol sets, and uses compiler response files plus a forced macro header.
   tools/build/command.py enforces portable budgets before every supervised spawn: ≤131,072 bytes per
   argv/environment string including NUL, and ≤1 MiB aggregate with pointer allowance. It transports all
   macros once conservative post-quote compiler options exceed 64 KiB, preventing GCC’s own
   cc1/COLLECT_GCC_OPTIONS E2BIG after response expansion. Compiler descendants are protected by conservative
   post-quote budgeting; unsupported dependency/preprocessor transport is rejected closed, while only
   allowlisted file forms are forwarded and sanitized. Preprocessing transport is restricted to the exact
   null-output form with explicit -o /dev/null. Real-GCC/clang regressions exercise large macros, response
   files, dependency forms, diagnostics, cache identity, all example plans, and the x64-scale-sized plan; no
   success stub is used.

2. **The 60-minute test job.** Logs showed that the apparent ~30-minute “lint” cost was serial cold Zig,
   lifting, and wasm-opt work for generated example check-builds, not serial clang/GCC warning scans. The
   approved workflow splits that work into independent lint_js, lint_native, and lint_examples jobs. Unit
   files are assigned to two deterministic, setup-aware measured LPT shards; the scale file remains covered by
   the required scale job, and shard union is checked against Vitest’s complete inventory. E2E and scale
   remain separate jobs. The strict aggregate gate requires success, not merely completion, for every required
   job. Existing assertions, coverage, and test deadlines were retained. Reviewer approvals #289/#295 cover
   the fan-out, strict required gate and exact shard/scale union; final unit/e2e jobs remain 60 minutes, scale
   45, native lint 20, and the aggregate 5. Measured shard placement includes unique cold-example setup cost,
   not only test-file durations. The convergence test retains its 70,000-NOP workload and 180-second deadline:
   #309 removes redundant whole-module Asyncify before forced partitioning; #320 uses a 256-KiB forced budget.
   A separate 1-KiB-budget suspension fixture asserts ≥16 parts (observed 38), preserving large index-space
   merging, 300 checksum frames and actual parked-stack/JSPI assertions.

Transport review repairs also preserve relative -D/-U/-imacros semantics, native newline/trailing-backslash
behavior and original semantic cache inputs. Macro headers live in an owner/mode-checked 0700 safe directory
with canonical path grammar; dependency files and captured/inherited/file diagnostics never expose its random
path. Supported dependency discovery uses explicit separate -M/-MD -MF FILE -MT bgt; implicit/stdout/opaque
alternatives fail closed while transport is active. K23 finite stdin, inherited writer leases, process-group
cleanup and deadlines remain covered. Isolated old-helper/real-GCC-and-clang probes reproduced descendant
E2BIG and dependency/diagnostic/tokenization defects before the corresponding repairs; earlier
failing/interrupted suites are retained as such in reports/k33/ and the checkpoint history, not reused as
final green evidence.

3. **Portability.** The owned native GL/profile and x64 warning-only fixes split misleading statements and
   correct signedness without changing control flow. The real-GCC host gate covers the compilations that CI
   actually performs; target-only wasm/WASI/Windows guest sources are not falsely claimed as host-GCC builds.
