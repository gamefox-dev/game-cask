## Implemented contracts

### 1. Native scalar SSE/SSE2 forms

- AMD64 native `cvtsi2ss/sd`, `cvt(t)ss2si/sd2si`, `cvtss2sd`, `cvtsd2ss`, `comiss/sd`, `ucomiss/sd`.
  Correct register/memory widths, REX.R/B/W and extended GPR/XMM operands. Upper destination lanes survive
  scalar conversions. COMI/UCOMI clear OF/SF/AF, set ZF/PF/CF for unordered, and preserve unrelated EFLAGS.
- Decoder fixes GPR-versus-XMM classes and integer widths for conversion operands, MOVD/Q, mask extraction
  and insertion. The hot invalid spelling `cvtsi2ss xmm0,xmm0` becomes the actual GPR operand. Unsupported
  MMX conversion encodings fail explicitly instead of being executed as scalar SSE.
- All four guest MXCSR numeric RC modes, ties-to-even, truncating forms and integer indefinite, including
  infinities/NaNs and signed 32/64-bit boundaries. `x86_sse.h` rounds integer significands without host fenv
  dependencies or int64→double→float double rounding. Shared semantics and emission use the same primitives;
  independent known-answer cases supplement the differential oracle.
- Fixed scalar memory overreads in shared CVTSS2SD/CVTSD2SS and CMP forms. Page-edge tests assert exact read
  widths and the full CPU/RAM fault state. Native scalar/packed CMP predicates and SQRT are also supplied.

**Reviewer-confirmed FP acceptance boundary:** no MXCSR sticky exception-flag delivery, unmasked SSE FP
exception delivery, DAZ/FTZ or nondefault **arithmetic** rounding. These were existing documented limits and
remain so, not full IEEE/SSE exception certification. Requested conversion numeric RC, integer indefinite,
NaN/EFLAGS, upper lanes and memory widths are implemented and tested. Guest code using excluded control
modes still needs that broader runtime work; no new Windows FP exception subsystem is claimed here.

### 2. Import/external thunk path

Register-local regions **return and spill** before any host implementation executes. Their small ordinary
wrapper invokes the flat native driver, which calls the existing thunk handler directly when EIP enters its
registered range. Import veneers and indirect import pointers do not bounce through `interp_until` between
native code and the host API. The same handler still owns Win64 register/home/stack arguments, last error,
API metrics/traces and coverage. No second API implementation or optimistic success path is introduced.

Callbacks, suspension, growth, nonlocal transfer and scheduler work never execute with native register-local
frames live. The native driver checks transfer/pending/count boundaries before further work and after a thunk.
Actual-runtime regressions exercise five Win64 arguments, stack restoration, metrics, pending work, transfer
and a nested guest callback from a thunk. The ordinary both-width thread/CRT/exception fixtures remain mandatory.

### 3. Foreign-owner chaining, lookup and interior entries

- Each AMD64 generated owner has an `N_<owner>(uint32_t)` non-suspending **step** and an `F_<owner>(void)`
  wrapper. The registry gains an additive internal native-step pointer; i386/legacy entries use NULL.
  `x86_run_native` resolves the next step through the registry and loops across **all owners**, not only its
  original owner. Guest recursion and tail cycles do not recursively call F_* wrappers or grow C frames.
- Each interpreter/invoke scope installs its return-PC/stack floor; nested calls/callbacks save/restore the
  scope. Chaining stops **before** consuming the requested return continuation, even when it is itself native.
  Legacy/override entries, unsupported forms and cold quantum work return to ordinary dispatch.
- Exact-PC 1024-slot direct-mapped lookup cache, including misses. Registry replacement invalidates every slot;
  force-interpreter and existing execute-permission checks run on hits too. Tests cover collisions/ranges,
  replacement, misses and NX changes. The cache holds immutable functions, not pointers into guest memory.
- Native interior entries for SSE instructions and regions of <=8 instructions. Suffix guards and exact counter
  debt run before entering code that assumes them. Cold flag replay excludes unexecuted prefixes. Other interior
  addresses retain truthful bounded shared semantics; this is **reduced**, not universally eliminated, dispatch.
- Reviewer explicitly authorized the minimal `tools/build/chunks.mjs` registry-format adapter/tests. It accepts
  exactly four-field rows, verifies native symbol/owner consistency, emits exact wrapper/step signatures, and
  rejects malformed rows rather than dropping them. No K10 counters/instrumentation/Asyncify/build policy or
  K12 heap implementation was edited.

### Audit / rejected broad suffix experiment

The first implementation emitted native suffix initialization at every instruction. x64-cpp size-preset wasm
measured **2,670,595 → 4,868,849 B (+82%)**. That policy was rejected, not hidden. Native suffixes were narrowed
to SSE/tiny regions; final x64-cpp is **2,799,757 B (+4.8%)**. Full-instruction native suffix initialization needs
a compact/shared redesign before enabling it generally.

Native common set: existing MOVUPS/APS/DQU, MOVSS/SD, AND/ANDN/OR/XOR, ADD/MUL/SUB/MIN/DIV/MAX; new scalar
conversions/COMI/UCOMI, CMP predicates and SQRT. Still generic: MOVD/Q/half moves, mask extraction/insertion,
SHUF/unpack/pack, packed integer ALU/shifts/saturation, packed numeric conversion (5a/5b/e6), reciprocal/rsqrt
and MXCSR state operations. These use the existing shared core, not success stubs or mislabeled specialization.
No unrestricted SSE2, AVX, self-modifying code or i386 SSE execution expansion is claimed.
