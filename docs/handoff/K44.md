## Fix and audit

The BGTSTATE v2 wire layout is unchanged. Imported raw `blob8` values are copied to an
allocation whose offset is zero when the transport view is not 8-byte aligned. `blob32` data is
assembled in owned storage before its `Uint32Array` is constructed. At checkpoint replay,
`restoreCheckpointItems()` applies the same 8-byte alignment normalization to every GPU upload
`Uint8Array`; already aligned uploads remain zero-copy. This protects WebGL2’s Float32/Int32/
Uint32/Uint16 typed upload views and also future Float64 views. DataView consumers are naturally
offset-safe. Old/unknown version and malformed stream rejection remains covered.

The typed-view audit found: WebGL2 `view()` is the only production renderer site consuming
untrusted replay upload backing offsets; WebGPU depth upload uses DataView; wasm memory,
command buffers, mapped/native buffers, readback arrays, vertex arenas, and codec float-bit
helpers are newly allocated or naturally aligned. Clone’s Uint8/Uint32 alias handling is
intentional and replay normalization is the safety boundary. A fresh static review found no
P1/P2 defect; it noted only that clone has no independent coverage for arbitrary typed-view
aliases, which is outside this byte-upload bug.

with offsets 1, 2, 3, 4, and 7, repeated restore/compaction, 300-update lead-in, 12 restore runs,
eight suffix frames per run, hashes, pixels, native upload bytes, metadata, and diagnostics.

- **Pre-fix browser:** exit 1. WebGL2 failed all four default-fixture cases (both suspension

  WebGPU’s memory path was already safe because its depth upload uses DataView; its binary path
  failed the imported-alignment invariant before the fix. This is honest backend-specific evidence,
  not a synthetic WebGPU rendering failure.
- **Post-fix focused browser:** 82 passed, 0 failed, 0 flaky across WebGL2 and WebGPU, both
  Asyncify and JSPI, including separate memory and binary transfer cases. All eight default
  fixture measurements reported exact suffix equality, aligned imports, equal native bytes,
  stable metadata, and zero diagnostics/command errors.
