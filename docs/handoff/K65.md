# K65 — exact Asyncify instrumentation from the linked wasm, verified artifacts, names

Branch `kit/lane/K65`, base `f5f988d`. CC0 fixtures only; no installs (the pinned npm Binaryen 132 was enough), no
network. Evidence: `/Volumes/CaskWork/lanes/scratch-K65/` (`k65/prepare-*.json`, `k65/time-*.json`, `*.log`).

## Why the Asyncify artifact was slow (Q119)

Two over-approximations, both worst in the partitioned (>32 MiB code, MMX8) path:

1. **Placeholders.** A partition replaced every other batch's bodies with `call bgt.yield; unreachable`, so every
   function calling into another batch was "suspending" and instrumented: generated `R_` regions (exact emitter,
   also used by fast mode for functions >4096 instructions), CRT leaves, `x86_rd*/wr*`, `x86_simd`, `x86_x87`,
   `x86_try_import`, `xl_imul_wide`... all hot under lifted code.
2. **Indirect calls.** Binaryen treats every `call_indirect` as possibly suspending.

Generated `N_` native steps were already excluded (removelist) in both shapes, which is why whole-module fast-mode
fixtures were close to JSPI before (K52).

## What changed

- `tools/build/wasm-callgraph.mjs` (new): bounded binary scan of a linked module (no IR, no instantiation; ~0.5 s
  for 15 MB). Records direct calls, `call_indirect` signatures, `ref.func`, element segments, exports and global
  accesses. `suspendingSet` = functions that can reach `bgt.yield` by direct calls plus `call_indirect` sites whose
  signature (structural) equals that of a suspending function that can be in a table (all element segments, every
  `ref.func`; if a table is imported/exported, every exported and imported function). Cut points (the existing
  `N_` removelist) neither suspend nor propagate, exactly Binaryen's removelist semantics. Opcodes outside MVP +
  bulk-memory/sign-ext/sat-conv (SIMD, threads, EH, GC, tail calls) fail closed.
- `tools/build/asyncify.mjs`: default `analysis: 'precise'` (`BGT_ASYNCIFY_ANALYSIS=binaryen` keeps the old one for
  A/B). The set goes to Binaryen as an exact `asyncify-onlylist` response file of canonical identities.
  - Partitioned: one plan from the raw module (index space unchanged); placeholders yield only for functions in the
    set (they no longer decide anything: the onlylist does).
  - Whole-module: `-O2` first (identity names kept), plan computed on the optimized module, then
    `--optimize-level=2 --asyncify` (sets the level without re-running O2). Planning before O2 was wrong: O2
    inlines cut `N_` steps into their callers (`R_` regions), moving the steps' suspending calls into functions the
    pre-O2 list did not contain. The verifier caught this on x64-cpprt (186 functions); the two-pass form fixes it.
  - `verifyAsyncify` re-analyses the **final** artifact with the same cuts: every function that can reach the
    yield must reference the Asyncify state global (identified via `asyncify_get_state`). Otherwise the transform
    throws with a shortest call chain (e.g. `run -(call_indirect)-> deep_ind -> d2 -> d1 -> d0 -> yield`) and
    publishes nothing.
  - Every Asyncify artifact gets the standard name section (original names restored through the identities;
    Binaryen helpers keep their names). Profiles of the partitioned artifact show names, not `wasm-function[N]`.
  - Each run prints `#bgt-asyncify {stats}`; the build caches it next to the wasm (`.names` sidecar, now always
    present) and records `asyncify_analysis`, `asyncify_functions`, `asyncify_suspending`, `asyncify_instrumented`,
    `asyncify_partitions` in `manifest.pipeline.metrics`. Cache key `bounded-asyncify/v2` includes the call-graph
    module and the analysis mode.
- `tools/build/binaryen-runner.mjs`: the exact pre-list names functions an earlier pass removed; Binaryen warns
  once per name on fd 2. Those lines are counted and summarized; all other stderr is forwarded line by line.
- `platforms/x86/x86_rt.c`, `x86_guest.h`, `platforms/win32/w32_core.c`: the dynamic half of the cut-point invariant.
  `x86_run_native` counts live native-step frames (`x86_native_live`, saved/restored around each `step()`), and
  `wait_host` calls `x86_check_suspendable()` right before the single `bgt_yield`. If a step frame is live it
  increments `native_step_suspensions` and, **in the Asyncify artifact only**, faults ("suspension requested inside
  a generated native step") instead of unwinding through uninstrumented frames. Under JSPI (which suspends any
  stack correctly) it only counts (coordinator ruling vK65). The artifact is told apart by a 16-byte volatile
  marker in `x86_rt.c` data that `asyncify.mjs` rewrites `...JSPI` -> `...ASYN` in the Asyncify output only
  (`markAsyncifyArtifact`; more than one occurrence fails the build); metrics `asyncify_artifact` 1/0.
- `build.mjs`: profile names no longer appended separately (already in the artifact); `BGT_PROFILE_NAMES=1` still
  writes `profile-map.json`.
- Docs: `docs/suspension.md` ("Exact suspension set (K65, default)"), `docs/pipeline.md`.
- Bench: `tools/bench/k65-fixture.mjs` (generated CC0 Win64 guest: 1,500 distinct functions with switches, integer
  mixing, SSE doubles, direct call chains, a function-pointer table, CRT memset/memcpy, QueryPerformanceCounter
  every 64 calls, one Sleep = one present per frame), `k65.test.ts`, `k65.config.ts`.
- Tests: `tests/unit/asyncify-precise.test.ts`, `tests/unit/asyncify-precise-pipeline.test.ts`; cache-key test
  extended; CI shard costs added.

## Notes and follow-ups

- Static set size is dominated by `F_` wrappers (1,576 of 2,329 on k65-fast; cold) and API/profile code reachable
  from thunks. In fast mode `x86_fast_exec` (generic instructions) and `x86_fast_quantum` stay instrumented because
  their static graph reaches the scheduler; the runtime guards (`x86_fast_inline`, quantum probe) are dynamic. If a
  game executes many generic instructions, a non-cooperating `x86_exec` entry would remove that edge.
- Whole-module mode now parses the module twice (O2, then Asyncify): x64-scale 126 -> 163 s cold; k65 unchanged.
- Name sections add bytes to every Asyncify artifact (already present in JSPI artifacts); no separate symbol map.

## Coordinator ruling applied (vK65)

The native-step guard faults only on the Asyncify artifact; under JSPI it is a diagnostic counter
(`native_step_suspensions` in metrics). Test `tests/unit/native-suspension-guard.test.ts` (CC0): a test-only
override enters a "native step" through the real `x86_run_native` driver that waits for a frame (a simulated
analysis miss). Asyncify artifact: faults with the guard message before the guest result is logged. JSPI artifact
of the same build: the guest completes (`guard result 12`), `native_step_suspensions: 1`, `asyncify_artifact: 0`.
Without the override, Asyncify: `native_step_suspensions: 0`, `asyncify_artifact: 1`.
