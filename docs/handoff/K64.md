# K64 — memory attribution, packaging/load metrics, iPhone-class memory budget

Branch `kit/lane/K64`, base `f5f988d` (v0.3.0-dev.37). CC0 fixtures only; no game files, no installs, no network.
Evidence: `/Volumes/CaskWork/lanes/scratch-K64/` (`measure/before.json|after.json` + logs, `e2e-*.log`,
`pm-x64-gl.json`, `package-metrics-x64-gl.json`).

## What changed

1. **Memory attribution** (`bgt/runtime/memory.ts`, pure; wired in `runtime.ts`): `diagnostics().memory` and
   `__BGT_TEST__.memory()`:
   - `wasm`: linear bytes, high-water mark, the module's declared initial memory (parsed from the memory section by
     `wasmMemoryLimits`), module bytes; `compiledBytes: null` (machine code is not observable).
   - `guest` (Win32 profile, from `bgt_metrics`): flat-guest committed address, heap, **new** `virtual_live_bytes` /
     `virtual_peak_bytes` (VirtualAlloc; reserve = commit in this profile), host arena used/peak/reserved, GL frontend
     guest copies. All inside linear memory, so not added again to the total.
   - `gpu.reserved`: the §13 decoder reservation by kind (`GpuState.reservedByKind`, sums to `reservedBytes`);
     `gpu.native`: what each executor allocated, from its own tables, no GPU queries (`memory()` on `WebGL2Gpu` and
     `WebGPUCommands`): buffers (guest and padded sizes), textures (allocated levels, depth/stencil part),
     renderbuffers (always 0: the kit uses textures for attachments), internal (logical screen, WebGPU rename pool and
     retired buffers, scratch) and the executors' CPU recovery shadows; canvas estimate (drawing + swap buffer).
   - `js`: preloaded assets, stream chunk cache, decoder buffer shadows, executor recovery shadows, v0.2 texture-table
     shadows, queued audio, Chromium `usedJSHeapSize` when present.
   - `estimate`: disjoint components (wasm linear + module + GPU native + JS held), peak, budget, `status`.
2. **Budget** (task 3): default **1.5 GiB**; game.json `"memoryBudget": {"bytes": N}` (copied into the manifest by
   `build.mjs`), `?memorybudget=1536m|1.5g|BYTES`, or `RuntimeOptions.memoryBudgetBytes` (precedence option > URL >
   manifest > default). Over budget is `status: "over-budget"`, a warning; a malformed URL value is reported in
   `backendNotes` and ignored. Peak total is sampled every 30 presents and on every read.
3. **Load metrics** (`bgt/runtime/load-metrics.ts`): `diagnostics().load` / `__BGT_TEST__.loadMetrics()`: marks
   (manifest, wasm, assets, ready, first frame, first update), spans (instantiate, init), wasm streaming and why not
   (`streamingReason`), Content-Type/Encoding, resource-timing transfer/encoded/decoded sizes, compression ratio.
4. **Packaging tool** `npm run package:metrics -- --game ID [--serve] [--browser] [--url BASE] [--brotli 11]`
   (`tools/report/package-metrics.mjs`): raw/gzip/brotli per kind (wasm, js, data, meta), serving check (MIME ->
   streaming compile, Content-Encoding, COOP/COEP) and a free-running Chromium load with phases + memory. Writes
   `reports/package-metrics-ID.json`. `npm run bundle -- --game ID --precompress` writes `.br` (q11) / `.gz` beside
   compressible bundle files (kept only when >= 5% smaller).
5. **Cheap fixes**:
   - `compileVerifiedWasm` writes download chunks straight into one manifest-sized buffer (was: chunk list + a
     concatenated copy, 2x the module at the load peak); `fetchBytes` does the same for preloaded assets and now
     rejects a size different from the manifest (integrity).
   - WebGL 2 texture recovery shadows are allocated on the first upload of each level, never for render targets,
     depth or grown levels; mip generation from a never-uploaded base keeps no zero chain (both backends; WebGPU
     allocated a zero base + chain on every such TEXTURE_GENERATE_MIPS). Recovery recreates such levels zeroed,
     which is what their uploaded contents were; rendered contents were and are lost on recovery.

## Findings (biggest items on the fixtures, and what they mean for MMX8)

| item | fixture evidence | avoidable? |
|---|---|---|
| WebGL2 texture shadows of never-uploaded levels | 245–330 KB -> 20–312 B per fixture (above) | **fixed** |
| wasm + asset load-time copies | 2x -> 1x (code) | **fixed** |
| x64 flat guest: linear memory = static/initial 40.0 MB + 64 MiB host arena slot + guest window to the highest mapped address (heap at `W32_HEAP_LO` 64 MiB) | x64-gl linear 174.3 MB, host reserved 19.1 MB, guest committed 67.2 MB, heap 96 B | address space, mostly untouched zero pages (not resident); shrinking needs a layout change, see decisions |
| initial memory 40 MB: BSS (`x86_pages` 4 MiB, `x86_protection` 1 MiB, metrics JSON buffer 8 MiB, owner census 6 MiB, ...) | win32/x64 initialBytes 39.98/40.04 MB vs native 1.3 MB | untouched unless written; the 8 MiB JSON buffer is written only to its used length |
| GL buffer bytes held 4x: GL frontend guest copy (wasm), §13 decoder shadow (JS), executor shadow (JS; load-bearing on WebGL2 for index rebasing / wide strides), native | x64-gl: frontend 120 KB live / 2.0 MB peak, decoder 8.3 KB, executor 8.3 KB | not cheap; for MMX8 read `guest.glFrontendBytes` + `js.gpuDecoderShadowBytes` + `gpu.native.shadows.bufferBytes` |
| uploaded texture recovery shadows (both backends) | small on fixtures | needed for device-loss recovery; an opt-out is a decision |
| compiled machine code | not observable (`compiledBytes: null`) | for a 273 MB module likely the largest unattributed part of WebContent RSS |

The MMX8 GPU reservation (397–478 MB) was not over-counted by the decoder on these fixtures: native bytes equal the
reservation exactly. On WebGL2 the eager shadows used to add up to the never-uploaded share of it again in JS heap.

## Review vK64 fixes (3 low findings)

1. **Local path in package-metrics output (fixed).** `artifacts.dir` and the console lines are repo-relative inside
   the repo, else the basename (`displayPath`). Unit: the JSON of a temp-dir report contains neither the temp dir nor
   any string starting with `/`.
2. **Peak missed the load peak (fixed + documented).** The estimate is now also sampled at load milestones: game.wasm
   compiled (its verified download buffer counted as the new `js.loadBuffersBytes`), instantiated, initialized,
   ready, first frame; then every 30 presents and on every read. `estimate.peakSampling` and docs/performance.md
   say it is a sampled peak; spikes between samples and engine-internal compile buffers are not seen. Unit: a
   milestone sample with a 30 MiB load buffer sets the peak that later samples keep.
3. **Weak shadow bound (fixed).** The e2e bound is now `textureBytes <= textures - depthStencil` and `< 1%` of the
   native texture bytes on x64-gl; the old eager shadows (288,804 B vs 288,788 B native, 272,384 B depth/stencil)
   fail both. New browser test on both backends: a partially uploaded (lazily shadowed) level, a render-target
   texture with a mip chain generated from a never-uploaded base and a depth texture survive a real loss
   (WebGL2 `WEBGL_lose_context` lose + restore; WebGPU old device destroyed, restore onto a new device):
   texel readback before and after is exact (green 4x4 region, zeros elsewhere and in the zero-generated levels),
   and the shadows are exactly one 8x8 RGBA8 level (256 B) before and after.

4. **Linux CI: `runtime-recording` / `runtime-recording-failure` units (fixed).** These tests build the runtime with
   `Object.create(BGTRuntime.prototype)`, so K64's class fields did not exist and the first-frame mark threw. The
   frame path now guards the load marks, and every peak sample goes through `samplePeak()`, which skips a runtime
   without the bookkeeping and records (never throws) a failed sample. Tests unchanged.

## How a port uses this (Mega Man porter)

1. Per-component breakdown in a probe or port test after reaching the scene of interest:
   `const m = await page.evaluate(() => __BGT_TEST__.memory())` — record `m.estimate.components`, `m.wasm`,
   `m.guest`, `m.gpu.reserved`, `m.gpu.native` (buffers/textures/internal/shadows) and `m.js`. Compare
   `m.estimate.totalBytes` with the OS process RSS you measured (WebContent + GPU process); the gap is compiled code
   plus browser/driver overhead.
2. Budget: put `"memoryBudget": {"bytes": 1610612736}` (or your target) in `port/game.json`, or pass
   `?memorybudget=1.2g` for a run; read `m.estimate.status`.
3. Load/packaging: `npm run package:metrics -- --game <id> --serve --browser --brotli 11` (also `--backend webgpu`,
   `?suspension=jspi` via the dev page) gives artifact sizes raw/gzip/brotli, streaming-compile status, time to first
   frame and first interactive update. For a deployment: `npm run bundle -- --game <id> --precompress`, deploy, then
   `npm run package:metrics -- --game <id> --serve --url https://host/` to see the MIME and Content-Encoding it sends.
4. iPhone: the estimate is not device RSS. Real-device memory and load time stay a **hardware gate**; report them
   separately (Safari Web Inspector Timelines / Instruments).

## Coordinator decisions needed

1. Guest layout for flat x64 games: place the host arena after the guest window or size it on demand, and start the
   heap lower than 64 MiB, to shrink linear memory (address space, not proven resident). Not done: it changes the
   guest memory map.
2. Optional opt-out of uploaded-texture/buffer recovery shadows (e.g. manifest `gpu.recoveryShadows: false`, device
   loss then signals `targetsLost` for every texture). Would remove one CPU copy of every uploaded byte; changes the
   recovery contract, so not done.
3. Whether the decoder's buffer shadow could be shared with the executor's (one JS copy instead of two): needs an
   ordering design (the decoder runs ahead of the executor within a frame).
