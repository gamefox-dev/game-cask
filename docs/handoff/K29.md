## Diagnosis and agreed design

K13 returns/spills native steps before APIs and recognizes thunk-range PCs in `x86_run_native`.
It does **not** statically identify IAT call-site operands. In particular generated `JMP_IND` veneers
read their operand, set `XE_INDIRECT`, enter local dispatch, miss the guest labels, and report a reason-5
exit before the driver recognizes the profile thunk. CALL_IND also ends the region and takes the driver's
runtime thunk path. Copied IAT registers have no provenance tracking. Thus zero interpreted/generic
instructions do not imply zero import dispatch/boundary work. The profile additionally scans thread API
names and other registries during ordinary thunk calls. No target game was opened or run to re-census it.

Reviewer **#240** explicitly accepts:
- statically recognized IAT/provenance hints plus a full-width actual-target guard;
- direct call-site execution only for explicitly typed non-suspending leaves, after full spill/reload;
- bound outer-driver execution for potentially suspending APIs;
- the existing dynamic path for changed slots/targets.

Never call a callback/yield/SEH-capable import with an Asyncify-excluded N_* frame live.
Reviewer **#242** preserves the existing documented abort-on-memory-fault contract; new recoverable
access-violation SEH delivery is a separate future lane. Explicit RaiseException/unwind must remain non-leaf.
Report exact faults/state, not a new Windows access-violation-SEH capability.

## Implemented, not yet validated

- `tools/x86/lift64_imports.h`: conservative forward CFG IAT provenance for 64-bit MOV/copies,
  agreeing joins and nonvolatile registers across calls. Unknown/generic operations drop hints;
  volatile registers are killed at calls. Direct memory operands remain runtime reads.
- `tools/x86/lift64.h`: guarded CALL_IND/JMP_IND paths. Spill all 16 GPRs, flags and clocks before a
  leaf; reload afterward; retain continuation coverage and native counting policy. Import tail veneers
  can return directly without the reason-5 exit. Changed operands retain the dynamic path.
- `platforms/x86/x86_guest.h`, `x86_rt.c`: loader bindings, lazy generation-invalidated per-site cache,
  full-width equality guard, distinct leaf/bound signatures, deferred bound-call token consumed BEFORE
  callbacks/suspension. Actual loaded register operands are guarded, NOT a re-read of the slot: a register
  loaded before a later IAT patch still calls its original target. No per-call allocation.
- Win32 loader binds only actual profile thunk addresses (not guest exports/data). Existing shared thunk
  dispatch caches the thread registry lookup. Leaf envelope retains argument tracing, home-space writes,
  RAX/return-stack semantics and profiling; metrics add `thunk_dispatches`, `direct_import_calls`,
  `leaf_import_calls`. These counters have not yet been exercised in the new fixtures.
- Explicit CRT leaf adapters: malloc/free/calloc/realloc, narrow/wide strlen/strcmp/strncmp.
  They call existing checked implementations. Thread leaves: GetLastError, SetLastError,
  GetCurrentThreadId, TlsGetValue, using authoritative per-thread TEB state.
- **Last edit before checkpoint:** leaf wrapper now returns accepted/refused. A non-consuming
  `w32_thread_leaf_ready` guard refuses callback scopes, transfers, pending scheduler work and deferred
  results, avoiding the ordinary thread envelope's possible `park_native` suspension. Runtime counters
  increment only for accepted leaves. This edit and its updated fixture signatures are untested.
- Shared CRT correctness repair found in passing: strlen/strcmp-family pointer arithmetic is full-width
  until checked reads, rather than silently aliasing high Win64 pointers to low guest memory. Bounded
  comparison uses full size_t width. Both direct and ordinary/interpreted import paths share the fix.
  No allocation/string-copy shortcut or strcmp-name-specific lifter rule was added.
