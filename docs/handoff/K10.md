## Part 1: how the porter uses it

`docs/pipeline.md` documents every field, sampling and overlap caveat. Runtime `cpu_profile` contains category/API
sample times, top 32 retained exits by address/reason, interpreter-entry instruction counts and explicit drop counts.
`host_profile` adds cumulative update/render/I/O-wait and sampled BGT imports; browser `runtime_profile` adds GPU
submit/draw wall and streamed VFS read/fetch timing. Browser HTTP decompression is **null**, inseparable from fetch;
guest decompression belongs to CPU categories/CDP. Inclusive estimates are not disjoint wall-time partitions.

`guest_instruction_clock` is raw `X.tsc`, not exact threaded process retirement (context restore and pre-execution
quantum attempts matter; i386 leaves it zero). K11 was told this limitation. No false exact instructions/s claim.

```sh

npm run probe -- --game ID --script ./explore.mjs --cpu-profile 1100:1700 --out reports/probe/perf
```

The probe brackets `p.step/click/key` at actual update boundaries, saves DevTools `cpu.cpuprofile`, guest-address
mapping and machine resources at start/end. Direct page stepping/tour internals bypass the interceptor. Unavailable
`ps` data is null/EPERM, never fabricated. CPU sampler interval is 1ms, opt-in. Named synthetic browser smoke:
**300 updates, 35 mapped nodes, zero unmapped wasm nodes, no errors** after the no-`-g` implementation.

## General causes removed / measured

- Generated discovery hooks use a **65,536-slot wasm-local direct-mapped cache** and 4096-record queue. New kind bits
  flush at pressure, waits, normal update return, metrics and explicit faults. Collisions may re-report, never discard;
  host independent capacity/overflow enforcement is unchanged. Snapshots flush before observing entries/drop counts.
- Strict builds have no host recording crossings; local membership checks remain at all handled dynamic entries,
  including AMD64 in-region indirects, i386 resolved tables and direct/tail override calls. Host restrictions intersect
  compiled bounds through additive ABI subsections, C/TS mirrors and the shared host on both backends. One actual
  first-entry observation preserves existing browser evidence assertions; missing-code records remain visible.
- Asyncify excludes only exact generated wrapper **definitions** intersected with linked symbols. No wildcard or
  ignore-indirect shortcut; i386/shared semantics/dispatcher/scheduler/overrides remain conservative. Large argument
  lists fall back safely. A real handwritten Win64 override yields twice; an entirely overridden selection also works.
  The pre-existing AMD64 `--skip` duplicate-symbol bug was fixed with an exact-entry override registry record.
- Coverage → re-lift still converges on the >70k-insn indirect/interior fixture in two builds, then matches strict and
  interpreter runs. No recording was filtered/forged and no oracle/test assertion or tolerance was weakened.

Committed measurement details: `tools/bench/README-execution.md`, `k10-execution.json`, `k10-asyncify.json`,
`k10-profile-overhead.json`. Each labels source/worktree, same toolchain, resource pressure, cache state, raw samples,
wall/category/generic counts and method. Short CRT timings are noisy: a measured 2.13× over the reference is not a
