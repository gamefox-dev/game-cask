## What changed (`platforms/win32`)

**Scissored and masked glClear (`w32_gl_draw.h` api_Clear).** Was GL_INVALID_OPERATION whenever GL_SCISSOR_TEST was
enabled or any colour/depth/stencil write mask was not full. Now: masks remove what the clear touches (per draw-buffer
colour masks; depth with glDepthMask(GL_FALSE) and stencil with mask 0 are dropped). If every touched buffer is still
cleared whole (no scissor or a box covering the target; colour masks full or empty; stencil mask 0 or 255) it stays a
PASS_BEGIN load clear, now of exactly the touched attachments (per-attachment load flags). Otherwise: one pass with
LOAD, SCISSOR when enabled, and §13.9 CLEAR_BUFFER operations (per colour attachment with its mask, then DS / depth /
stencil with depth-write bit and stencil mask). An empty scissor box sends nothing. Both forms are one batched list
(`submit_deferred`). RGB-only formats keep alpha 1. Integer colour buffers (contents undefined after glClear in GL) get
the truncated clear colour in the matching class. Metric `gl_partial_clears`. `scissor_rect()` is shared with
glClearBuffer and draws (64-bit edge arithmetic; draws previously added int32 scissor edges).

**Primitive modes by expansion (`topology`, `expand_run`, `expand_draw`, `draw`).** GL_LINE_LOOP, GL_TRIANGLE_FAN,
GL_LINES_ADJACENCY, GL_LINE_STRIP_ADJACENCY, GL_TRIANGLES_ADJACENCY and GL_TRIANGLE_STRIP_ADJACENCY were GL_INVALID_ENUM.
They are expanded on the profile side to the equivalent u32 list (POINT/LINE/TRIANGLE list topology): fan triangle i
= (0, i+1, i+2); loop = strip + (n-1, 0); adjacency modes drop the adjacent vertices exactly as GL 3.3 §2.6.1 renders
them without a geometry shader (triangle-strip-adjacency per the GL table: even j (2j, 2j+2, 2j+4), odd j (2j+2, 2j,
2j+4)). Provoking vertex (last) and winding are GL's. The list is drawn with DRAW_INDEXED from private index buffers
(wire handles from `buffer_handle`, never guest buffer objects): glDrawArrays fans draw a prefix of one static fan
list with `base_vertex = first` (no per-draw upload; the list grows by powers of two, at least 256 triangles);
everything else is generated and uploaded into a private 256 KiB+ index ring by a BUFFER_UPDATE at the head of the
draw's own list (one batched record: accepted or replayed together; disjoint ranges until the ring wraps, so WebGPU
does not rename). Transform feedback counts/cursors use the expanded list (fans capture as TRIANGLES, loops as LINES,
as GL). Draws whose expansion is empty (e.g. a 2-vertex fan) validate and send nothing. Pipelines are keyed by the list
topology, so fans share TRIANGLES pipelines. Metric `gl_expanded_draws`.

**Primitive restart.** GL_PRIMITIVE_RESTART was a counted "not rendered" approximation and glPrimitiveRestartIndex a
stub. Indexed draws with restart enabled whose element data contains the restart index (compared before base vertex;
never for u16 data when the index exceeds 0xffff) are expanded run by run (any mode, including lists: incomplete
primitives at a restart are dropped). The restart index is excluded from the max-index/attribute-bounds validation (it
is no vertex; before, restart 0xffff in u16 data made the draw fail GL_INVALID_OPERATION). Draws without a restart
index in their data are unchanged (the wire has no restart semantics, ABI §13.3).

**Entries implemented (were GLSTUB, GL_INVALID_OPERATION):** glDrawRangeElements, glDrawRangeElementsBaseVertex,
glMultiDrawArrays, glMultiDrawElements, glMultiDrawElementsBaseVertex (each sub-draw validated alone, first error
kept; Win64 index-offset arrays read pointer-sized), glStencilFuncSeparate / glStencilOpSeparate /
glStencilMaskSeparate (back compare and ops go to the pipeline's back-face words, which both renderers already honour;
a back reference/read/write mask that differs from the front one is the counted approximation "separate back-face
stencil reference/masks (front values used)"), glLineWidth / glPointSize (GL_INVALID_VALUE for <= 0; stored and
queryable; ALIASED/SMOOTH_LINE_WIDTH_RANGE and POINT_SIZE_RANGE report [1, 1], so GL's clamp makes width-1 rendering
exact), glHint (4 core targets), glPolygonOffset (state; rendering with POLYGON_OFFSET_FILL stays the K60
approximation), glPolygonMode (FRONT_AND_BACK only, as core; LINE/POINT is a counted approximation), glPrimitiveRestartIndex,
glFenceSync / glIsSync / glDeleteSync / glClientWaitSync / glWaitSync / glGetSynciv (fences are signaled when created,
see decisions), glGetInteger64v, glGetInteger64i_v, glGetBufferParameteri64v, glGetQueryObjecti64v/ui64v. Fixed the
32-bit stdcall argument size of glClientWaitSync/glWaitSync (GLuint64 timeout: 4 words, was 3).

**glGet state and limits (were GL_INVALID_ENUM):** BLEND_DST_RGB/ALPHA, BLEND_EQUATION_RGB/ALPHA, COLOR_WRITEMASK,
CULL_FACE_MODE, FRONT_FACE, all front/back STENCIL_* state, POLYGON_MODE, the four hints, PRIMITIVE_RESTART_INDEX,
line/point ranges and granularities, MAX_VIEWPORT_DIMS (4096), MAX_CUBE_MAP/RECTANGLE_TEXTURE_SIZE, TEXTURE_BINDING_CUBE_MAP (0),
MAX_ELEMENTS_VERTICES/INDICES, MAX_{VERTEX,FRAGMENT}_UNIFORM_{COMPONENTS,VECTORS} (from the real uniform range),
MAX_{VERTEX,FRAGMENT,COMBINED}_UNIFORM_BLOCKS (7), MAX_VERTEX_TEXTURE_IMAGE_UNITS (8), varying components (60, WebGL 2's
15 vectors), MAX_CLIP_DISTANCES (8), MAX_DUAL_SOURCE_DRAW_BUFFERS (0), NUM_COMPRESSED_TEXTURE_FORMATS (0),
CONTEXT_FLAGS (0), SAMPLE_BUFFERS/SAMPLES (0); glGetFloatv BLEND_COLOR, DEPTH_RANGE, LINE_WIDTH, POINT_SIZE,
POLYGON_OFFSET_FACTOR/UNITS.

**Error census (`w32_gl.c`, `w32_core.c`).** Every `fail()` increments `gl_errors_raised`; the API wrapper counts, per
entry point, the calls during which an error was raised (`gl_error_calls`: `{"glClear": n, ...}`, nonzero entries in
table order; stubs count too). This includes synchronous host rejections surfaced through `fail()`; deferred batch
rejections replayed at a later flush are not attributed. A porter can read it from `metrics()` on the real game to see
which GL calls still fail.

## Audit result (what still raises errors for this game class)

Not implemented (still GLSTUB): glProvokingVertex (FIRST convention not rendered), glVertexAttrib{1..4}{d,s,N*,I*}
variants (integer current attributes need integer constant slots), glEnablei/glDisablei/glIsEnabledi and
glGetBooleani_v (per-draw-buffer blend), glClampColor, glCopyTex{Sub}Image1D/2D/3D, compressed textures, 1D
textures/attachments, glFramebufferTexture/TextureLayer, multisample textures and glSampleMaski, glTexBuffer,
glBindFragDataLocationIndexed, timer queries (glQueryCounter), glGetVertexAttrib*, glGetPointerv, glPixelStoref,
glLogicOp, glSampleCoverage. Occlusion/timer query targets in glBeginQuery remain GL_INVALID_ENUM.

**Found and not fixed (guest-visible, needs its own lane):** a draw whose GL viewport extends past the bound target or
has a negative origin fails with GL_INVALID_VALUE (`draw`: "viewport fits attachment"), but GL clips it. Hit in this
fixture by drawing to a 32x32 FBO with the initial 256x160 viewport. §13 VIEWPORT must fit the attachment, so the fix
is either a wire relaxation that each backend implements (WebGL 2 already applies the viewport in its vertex
transform; WebGPU would clip the native viewport and fold the rest into the transform) or a profile clip-space
transform with a clipped §13 viewport and scissor. Engines that keep a window-sized
viewport while rendering into a smaller target lose those draws today.
