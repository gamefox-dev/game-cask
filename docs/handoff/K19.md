## Root cause and general repair

The WebGL canvas is alpha:false, but WebGPU's retained logical RGBA8 screen kept source alpha after GPU
passes/BLITs. WebGPU canvas alphaMode:'opaque' does not rewrite the raw logical attachment/readback alpha.
Exporting its raw RGBA as a PNG (or later consuming that surface) exposes fractional/zero alpha: the supplied
striped/missing graphics are reproduced by the standalone replay, without running the game/profile.

WebGPU now performs a **native alpha-only store of 1** at GPU screen PASS_END and BLIT-to-screen boundaries,
before subsequent LOAD, screen-source BLIT, destination-alpha blending or readback. A cached fullscreen pipeline
writes ALPHA only, never RGB or offscreen textures; reset discards its device-local cache. Legacy 2D screen
pipelines write RGB only, retaining clear alpha1; offscreen legacy pipelines keep all channels. Presentation
explicitly emits alpha1, with the existing opaque canvas configuration. This is **not CPU readback masking**.
GPU pass-internal RGBA staging arithmetic remains unchanged, matching WebGL's completed-pass boundary.

Paths: bgt/renderers/webgpu/{gpu.ts,webgpu.ts,screen.ts}; contract in bgt/abi/ABI.md §13.1.
