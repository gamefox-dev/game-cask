# K36 - compiler/postprocess measurement (checkpoint)

Branch lane/K36, base 7a87925 (K35). Not final acceptance; no production optimization ships yet.
CC0 controls only, sandbox/no game inputs/web/installs/push. Port 5288. Raw evidence is outside the clone at /Users/dev/projects/pi-work/scratch-K36/.

## Actual settings

- pipeline.mjs:99/420 -O1 is the guest fixture PE compiler, not lifted C. Normal CRT fixtures use -O2.
- build.mjs CFLAGS compile all lifted C/chunks at -O2, wasm32-wasi, no LTO, bulk-memory/sign-ext/nontrapping conversion. Size/fast presets change emitter policies, not compiler level.
- Default AMD64 regions now use noinline without minsize; the selected clang level controls the speed/size tradeoff. The fast/size emitter presets remain separate policies for memory/ALU/counting, and fast no longer changes this attribute.
- JSPI is copied directly from linked clang output, with no Binaryen optimization.
- Whole Asyncify runs Binaryen -O2 before Asyncify, not a full optimization afterward.
- Large modules use K22 bounded whole-function partitions and fixed local optimize-instructions/precompute/simplify-locals/vacuum before and after. Whole-module interprocedural passes on placeholder shards are unsound.

## Measurements

- JSPI matrix a/jspi-{vm,flags,memory}: seven postprocess variants, nine alternating pairs after discarded warmup, 30 untimed plus 300 timed updates. O2/O3/O4 reduced bytes about 19%; VM was neutral/slightly slower, memory about 9% slower, while flags improved about 13%. Fixed local passes reduced bytes about 9% and improved VM about 1%, memory about 2.4%, flags about 11%. Small-transform cost was about 1.5 seconds versus 6-23 seconds for full passes.
- Asyncify matrix a/asyncify-{vm,flags,memory}: same variants. VM regressed about 0.56-0.86 ms per 300 updates; other controls were mixed/noisy. No post-Asyncify policy recommendation.
- Lifted-only O1/O2/O3/inline50/500 b/: both-mode 300-update oracle checks passed. The corrected adapter preserves original object order. The no-minsize O2/O3 controls (b3) also passed both-mode 300-update lifted/interpreted checks; interp_insns=0 and stubs=[] .
- Private diagnostic eligibility/results.json: adjacent same-block CMP/TEST to Jcc sites were VM174, flags155, memory155, for both size/fast. All had full 0x8d5 flags live after Jcc; zero eligible. Jcc successors are block starts whose guard/quantum boundaries observe incoming flags. No lazy descriptor emitted.
- x64-scale minsize-removal gate completed cold: 1,609,529 lifted instructions, 66,042,676 Asyncify bytes / 53,822,965 JSPI bytes, 689,969 ms build (389,115 ms compile, 200,826 ms Asyncify; six partitions). Against the same-source minsize baseline (65,489,494 / 55,064,988 bytes; 724,650 / 382,731 / 198,270 ms), deltas are +0.84% Asyncify, -2.26% JSPI, -4.79% build, +1.67% compile, +1.29% Asyncify: inside decision #361’s +5% size/+15% build guard. Its 300-frame lifted/interpreted oracle passed in Asyncify and JSPI with no interpreted instructions or stubs. The largest remaining fixture, x64-cpprt, built cold with 14,443,557 Asyncify / 15,159,838 JSPI bytes and 274,879 ms build (93,771 ms compile, 175,758 ms Asyncify). A same-source pre-change minsize control was then built with 14,369,964 / 15,008,859 bytes and 277,687 ms build (89,626 ms compile, 183,942 ms Asyncify): no-minsize deltas +0.51% / +1.01% size, +0.99% compile, -2.24% build, -4.48% Asyncify, inside the guard. Its 300-frame lifted/interpreted oracle passed in both Asyncify and JSPI with identical state hashes, interp_insns=0, and stubs=[] .

## Attribute history

minsize/noinline originated in daf1306 for bounded 256-instruction regions. 9b3f57a retained large-region size bias pending coverage hot lists; e859f6e made the small-region exception opt-in through K11. K11 records a <=64 experiment that was not retained. Size/build cost is therefore an acceptance input, not permission for a global removal.

## Deferred region-reservation design (not implemented)

A follow-up should jointly address fusion and block bookkeeping. Reserve a bounded maximum count to the next backedge/external/call/generic observation boundary at region entry; debit once, publish exact executed debt, and refund unused reservation on every exit. Backedges close debt and recheck. Failed admission must cold-replay old semantics at the exact PC, never yield early. Interior forward successors can omit reservation exits only after proving no independent observation. Keep permission-active/failed guards and incoming-flags landing paths. Include ordinary checked loads/stores: a fault uses static site offset plus path debt to publish exact completed count, refunds the suffix, and preserves RIP/TSC/retirement/GPR/flags and partial-store ordering. Initially close spans over variable/partial writers, RDTSC, generic, calls and suspension. Only after this proof may CMP/TEST to Jcc fuse. Reviewer deferred implementation to a later lane.
