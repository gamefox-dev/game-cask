## What changed

* **Detection in the normal flow.** `npm run inspect` now runs engine detection (tools/engine/detect.mjs) and prints
  per engine: version + release commit, runner, pack location + PCK format, the selected official runtime (threaded?
  COOP/COEP? verification level, cached or the fetch command), requirements, blockers, warnings, then
  `RECOMMENDED PATH: engineProfile|pipeline`. `reports/inventory.json` gets `engines` with a ready
  `recommendation.profile` (validated by `validateConfig` in tests). `npm run engine -- detect [DIR]` gives the JSON.
* **No operator authorization.** `requireOperatorAuthorization`, the brief marker and the outside policy file are
  gone; the choice is `engineProfile.allowed: true` + `engineProfile.choice` in `port/game.json`, echoed into the
  build manifest (`engineProfile.choice`) and trial record (`engineBundle` metrics). `trial:brief
  --allow-engine-profile` is accepted and ignored. CLAUDE.md (new "Detect the engine first" principle, workflow step
  1b, commands row), docs/engine-profiles.md (rewritten), docs/trial-brief.md, the inspect-game skill and the porter
  agent brief were updated.
* **Godot 3.x/4.x adapter** (tools/engine/godot.mjs; godot3.mjs is a compat re-export): PCK 1 and 2 from the public
  engine source (flags: encrypted directory, relative file base; per-file encrypted/removal; 4.4 path style), pack in
  header / trailer / PE `pck` section, normalization that changes only offset words (3.x) or the file-base word
  (4.0–4.2; 4.3+ embedded packs are byte-identical), project.binary reader (both majors), runner identity by
  version-signature regex + known release commits (custom/prerelease/Mono flagged; signatures inside an appended
  pack ignored). Blockers: GDNative/GDExtension, Mono/C#, encrypted pack/content/script, patch packs, additional
  packs, OS.execute, version without official runtime, 3.2 threads. Thread use is now a **requirement** that selects
  the threaded runtime (K45 treated it as a blocker; tests updated accordingly).
* **Runtimes** (tools/engine/runtime.mjs, zip.mjs, godot-releases.mjs): exact-version selection (no nearby fallback;
  non-threaded preferred, threaded when needed or only option). `npm run engine -- fetch ID` caches outside the repo
  in `$BGT_ENGINE_CACHE` (default `~/.cache/game-cask/engine-runtimes`). Levels: `pinned-member-sha256` (HTTP-range
  fetch of only the ~5–10 MB web template), `published-archive-sha512` (full 0.5–1.3 GB download, parallel ranges,
  checked against SHA512-SUMS), `manifest-crc32` (no published checksum; needs `--allow-unpublished`, recorded as
  weak). Offline `--from FILE.tpz`, legacy `engine:provision`. `engine -- pin ID` (maintainer) pins a member after a
  published-SHA-512 install. The Python ZIP helper was replaced by a strict Node reader (same 12 hostile-entry
  cases ported to the new unit test).
* **Bundle** (`npm run build:port`): runtime files the page loads, notices, `game.pck`, generated shell (3.2 legacy
  API or `new Engine(config)`; threaded shells fail loudly when not cross-origin isolated; Godot 4 header service
  worker off), `_headers` + `headers.json` (MIME, nosniff, CSP; COOP/COEP/CORP for threads), manifest with
  `metrics` (download/gzip/pack/runtime/wasm/bundle bytes, per file). The server serves the bundle's own headers and
  refuses a threaded bundle without isolation. Engine stderr is classified: Godot `WARNING:` lines (+ continuations,
  emscripten main-thread warning) become `diagnostics().warnings`; errors and context-free stderr still fail.
  Godot 3.2's XHR loader is covered by the network body evidence.
* leakcheck: v2 manifest hashes, `godot.worker.js`, audio position worklet, web template ZIPs and `.tpz` names.

## Coordinator decisions needed

1. **Weak verification for 25 releases.** 3.2–3.5.2, 4.0.x, 4.1, 4.1.1 publish no checksums; they work only with
   `--allow-unpublished` (CRC32 + TLS from the official host, recorded). Accept, or pin member SHA-256 for chosen
   versions after a reviewer download?
2. **Member pins** exist for 3.5.3 and 4.3 only; other published-checksum versions need a one-time full download
   (0.5–1.3 GB at ~1 MB/s here) before range fetches. Pin more (e.g. 3.6.x, 4.2.2, 4.4.1) in a follow-up?
3. Engine stderr warning classification (above) is a contract change of the engine test adapter: warnings no longer
   fail boots. Approve.
4. Thread use changed from blocker to requirement (threaded runtime, COOP/COEP); deployments must send the headers
   in `_headers`/`headers.json`.

## Known limits

Encrypted packs are blocked, never decrypted. C#/Mono and GDExtension/GDNative have no web path here. Detection
needs the runner (pack-only inputs are blocked). The bundle includes the observation-only test adapter. Engines
listed without an adapter fall back to lifting. Real-game validation remains with the porter (no game files here).
