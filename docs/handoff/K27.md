## Semantics / implementation decisions (need review)

- **platforms/x86/x86_atomic.h**: capture EA once; whole-span read+write preflight even on failed compare;
  enforce 16-byte CMPXCHG16B alignment; no partial atomic stores or flag/register mutation on failed preflight;
  failed compare writes original memory back. Sequentially consistent compiler/host fences surround transactions.
- Existing runtime is single-worker/cooperatively scheduled: no yield/API/growth inside these transactions.
  This does **not** implement parallel shared-memory wasm workers (would need synchronization for every access).
  Native bodies still spill/return before scheduler/host work; quantum checks remain before instructions.
- Shared x86_exec64 uses same transaction contract, but independent JS result/flag answers supplement differential
  tests. Fixes old XADD store-EA recomputation after base overwrite and CMPXCHG missing failed-write permissions;
  old pair operations also lacked full-span/alignment validation. Existing general abort-only fault model retained.
- Native atomic lowering disables whole-block guards to use exact operand preflight without generic guard exits;
  new cold-fault discriminator 4 spills locals then calls xa_check. Pair implicit GPRs and reverse MOVD/Q writes
  participate in used/written/dirty masks; atomic instructions get native suffix entries like SSE instructions.
- Bitwise SSE paths snapshot operands before writes, preserve exact upper lanes, use actual 4/8/16-byte memory
  widths, and do not perform FP arithmetic. Shared duplicate-move prefix semantics corrected too.
- Decoder rejects invalid LOCK/register encodings and unsupported MMX spellings previously misclassified as XMM.
  Audit impact of that rejection in full suites. FP exception/DAZ/FTZ limits from K13 are not expanded.
- Owned emitter files are **tools/x86/lift64.h**, **lift64_guard.h** (actual lifter location); no tools/build edits.
