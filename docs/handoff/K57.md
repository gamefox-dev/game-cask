## What changed

**Capacity reuse (`platforms/win32/w32_gl.c`, `w32_gl_buffer.h`).** `Buffer.size` stays the exact logical GL
store; new `Buffer.cap` is the native store and shadow capacity (`b->data` holds `cap` bytes). glBufferData that
fits (`size <= cap`, equal, smaller or larger) is one in-place BUFFER_UPDATE of the logical prefix, journaled
with its old size and bytes (`respec_in_place`). Every emitted native range (vertex/index/uniform bindings,
feedback captures, copies, readbacks) and every query, bound and mapping use the logical size, so the tail is
not observable. Growth beyond the capacity: deferred DELETE + one CREATE(cap) whose data is the new bytes plus
a zero tail (one command, so it takes effect whole or not at all); headroom = 1.5x the old capacity, 16-byte
rounded, total headroom <= 16 MiB, first allocations exact. A headroom CREATE the host rejects is retried exact
(in the call when unbatched, in the replay when batched), so headroom never causes GL_OUT_OF_MEMORY. GPU
generated provenance: the host clears it only for a write covering its whole store, so a whole-logical-store
write of a generated buffer with spare capacity uploads the whole capacity (glBufferData, glBufferSubData,
mapped uploads; glCopyBufferSubData from a CPU source becomes a whole-capacity update). The K47 fallback stays:
a rejected in-place update reruns the exact delete/create path. Counters: `gl_buffer_capacity_reused`,
`gl_buffer_capacity_grown` (new); `gl_buffer_respec_*` keep counting logical size changes.

**Batched allocations, feedback draws and blits.** Reallocation DELETE/CREATE (records `PR_RELEASE`/`PR_CREATE`,
handle occupancy committed on deferral), transform-feedback draws (`PR_DRAW` with cursor advance, generated
provenance, primitives-written query) and BLIT are ordinary batched commands; a replay withdraws exactly what each
rejected call committed (undo newest-first, redo accepted oldest-first, reject, then fixup: a buffer whose CREATE
failed is left empty as the unbatched accepted-DELETE/rejected-CREATE path leaves it; a store whose DELETE failed
is released later through the existing abandoned-handle retry). Shadow blocks replaced inside a batch are freed
only after it is settled.

**K53 replay bug found and fixed (ABI, additive).** The decoder skips only a failing command (§6 execution pass);
only framing/aggregate-budget rejections have no effects. K53's replay assumed whole-list rejection and resubmitted
every record, so accepted commands of a partially failed batch ran twice (surfaced here as a double DELETE). New:
- `bgt_submit_failures(dst, cap)` (bgt.h, host.ts): 0 / -1 (rejected whole) / N failed commands with
  {list offset, code} pairs. The profile settles a partial failure from the offsets without resubmission, and
  replays per call only a whole rejection.
- `BGT_CMD_FLAG_IF_HEAD` = 1 command-prefix flag (continuation lists only; was E_UNSUPPORTED): the command runs only
  if the latest unflagged command of the list took effect, else it is skipped (E_STATE, reported). The profile
  chains a draw to its uniform upload and a CREATE to its DELETE, so a draw whose upload failed never executes
  (the K53 exactness contract in `gl-materialization-failure.spec.ts` now holds without resubmission).
ABI §13.12 documents both (and corrects the K53 "whole-list, no effects" sentence).

**WebGPU (`bgt/renderers/webgpu/gpu.ts`, `blit.ts`).** In a merged frame, BLIT is encoded into the frame encoder
(after ending the open native pass; source/destination count as used; temporaries destroyed after the frame
submit; screen-opaque fixup in the same encoder). Compute-emulated feedback captures no longer submit and split
the encoder: gathers, compute pass, scatter and the resumed render pass share the frame encoder; every buffer and
texture the capture reads or writes is marked used, so later same-frame queue writes rename or split.
`?gpubatch=0` keeps the old per-pass/per-blit/per-capture submits for A/B.

**WebGL2 (`bgt/renderers/webgl2/gpu.ts`).** Production no longer polls getError around BUFFER_CREATE, BLIT or
feedback draws (pre-drain, setup, begin, draw); their native errors reach the deferred frame-end poll or are
drained as earlier unpolled work by the next checked transaction. Strict `?debug=1` polls every op as before.

## Findings

- WebGPU step wall rose (6.0 -> 7.2 ms) while every CPU measure fell: the step awaits `onSubmittedWorkDone`, and
  one submit at frame end serializes GPU-process and GPU work after the renderer instead of overlapping it with
  45 earlier submits. In a pipelined page loop this latency overlaps the next frame; not measured on the game.
- WebGPU main-thread CPU falls only 20%: 91 copy-on-write renames per frame (capacity-reused buffers are written
  while the frame encoder references them) replace 60 buffer creations; WebGL2 has no such cost.
- WebGL2 GPU ms (EXT_disjoint_timer_query) 1.09 -> 1.40 in single noisy runs; not investigated.
- Updates larger than ~128 KiB (upload + undo bytes > 256 KiB of the 1 MiB batch arena) still submit synchronously,
  as in K53; the game's buffer sizes are unknown here.
