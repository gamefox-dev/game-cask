## Implementation in 0f7d459

- `w32_gl_shader.h`: parse tables are transient. Compilation retains only preprocessed compiled-source
  snapshot + native module; link reparses that snapshot, then releases stage tables on success AND rollback.
  A failed compile drops its frontend scratch. Deferred deletion/shared attachments/current-program deletion
  semantics remain; replacement of an attached deleted stage also releases its old object.
- `glShaderSource` now replaces editable source without discarding the **last compiled snapshot/status**;
  linking must not implicitly compile newly supplied source. The native lifecycle test covers source replacement,
  compile failure, failed relink preserving the previous executable, explicit detach and shared deletion.
- `w32_gl_program.h`: reusable address-ordered best-fit spans with 16-byte headers, split/coalesce,
  64 KiB growth with exact-size fallback. Every backing byte still comes from **x86_alloc** inside the existing
  host reservation, not libc or guest heap. No reservation increase. Freed spans can be reused across sizes.
- Existing GL buffer CPU copies now use the same bounded reusable storage and return it on reupload/delete;
  texture/readback scratch returns its previous allocation when growing. Old bump-only copies otherwise competed
  with shader frontends forever. Native test covers **600 buffer reupload/delete cycles**.
- Compile/link failure wrappers always retain an app-readable reason and emit `glCompileShader: ...` /
  `glLinkProgram: ...` profile diagnostics. Allocation-failure counter deltas set GL_OUT_OF_MEMORY and
  append bounded-host-reservation reason even when warnings have filled the log. Canonical emitter allocation
  failures now carry a direct shared-frontend diagnostic. Failed command submissions are checked, not followed
  by a wait on an uncreated request. Link uniform-buffer submission failure no longer reports linked success.
- Metrics exported in `w32_metrics_json`: `gl_frontend_bytes` (live charged bytes including headers),
  `gl_frontend_peak` (live high-water), `gl_frontend_reserved` (backing retained/reusable inside host arena),
  `gl_frontend_allocations`, `gl_frontend_frees`, `gl_frontend_oom`. This shared GL host allocator
  also serves GL buffer copies and transient uploads; these metrics are not exclusively shader-source bytes.
- `tests/native/gl_frontend_driver.c` + `tests/unit/gl-frontend-memory.test.ts`: original CC0,
  actual profile APIs, bounded memory, recording/ownership-checking transport with injected backend failures;
  **not a GPU compiler oracle**. Six tests cover stress, source/lifetime/rollback, truthful OOM/recovery,
  split/coalesce/zero/overflow + **24,000 randomized allocations**, backend/transport failures and buffer reuse.
- Existing CC0 `examples/x64-glsl/glsl.c` now performs **256 real browser compile/link/delete cycles** with
  **80 retained linked programs**, variable large source strings / 24 helper functions and periodic relinks,
  before its unchanged eight known-answer pixel tiles. Browser assertions check stress marker, metrics and
  diagnostic reasons. Longer local test budget (180s) accounts for added work; no pixel/GL-error assertions removed.
