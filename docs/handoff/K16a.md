### Metrics / configurable bound

`w32_metrics_json` exports `host_bytes/host_peak/host_reserved/host_limit` (live charged / live high-water /
backing retained for reuse / bound). `host_consumers.runtime/gl/crt/file` each has
`used/peak/limit/allocations/frees/oom/backing_requested/shared_limit`. Per-consumer limits repeat the **same
shared limit**, not separate quotas or guaranteed headroom. Sum of consumer used = host_bytes; sum of consumer
backing_requested = host_reserved. Headers and alignment are charged, not RSS/static module data.

Legacy `gl_frontend_bytes/peak/allocations/frees/oom` retain GL consumer meanings. `gl_frontend_reserved`
records cumulative backing requested on behalf of GL (not total host backing and not a private reservation).
A consumer can borrow others' backing, so in general its own peak can exceed its backing contribution.
An initial migration accidentally mapped that compatibility metric to total host backing; browser tests
correctly rejected **26,935,296 B** against the existing **24 MiB GL bound**. Fixed the attribution, **without
raising/removing that assertion**. Full shared bound is independently asserted and per-consumer sums checked.

Every shared allocation failure logs via a fixed stack buffer and `bgt_log`, without CRT allocation/formatting:
consumer, requested size, consumer used, total used, reserved and limit. Both native stress and real wasm FILE/
CRT OOM tests cover truthful failure/recovery. No new BGT wire operation/capability/layout is added; these are
profile debug metrics on both backend paths.

`pipeline.memory.hostArenaMiB`: **integer 16..512, default 64 MiB**, build-time AMD64 flat reservation;
validated before pipeline work, passed to `X86_HOST_ARENA_BYTES` and repeated in the manifest. Default is NOT
increased to mask leaks: repaired 768-cycle / 96-live-program stress still plateaus at **18,284,544 B**, peak
**17,167,104 B**. Paged i386 retains its prior wasm32 address-space limit (its mapped guest pages also use host
backing); the flat-reservation option does not change i386. See `docs/pipeline.md` for full metric/config semantics.

### GDI hand-off — reviewer #127 expressly defers this migration

Do **not** silently count these as repaired. Reviewer scheduled a separate lane to keep Q50/Q51 critical-path scope:

- `platforms/win32/w32_replay.c` base buffers around lines53–68: separate **exact-size free list** layered on
  permanent x86_alloc. Deletes/compaction return blocks to that private list, not the shared host pool, and

  not logical replay live bytes. Risk: varied surface churn can exhaust bounded host storage despite logically
  dead/free replay buffers. Suggested repair: shared named GDI/replay consumer, release via shared free,
  preserve exact CPU replay/compaction/readback semantics and truthful missing-history/OOM accounting.
- `platforms/win32/w32_gdi.c`: `cpu_px` (~293), icon copies (~313), bitmap-from-DIB (~401) allocate
  permanent CPU pixels. `DestroyIcon` (~329) / `g_DeleteObject` (~607) discard object identity but do not
  return CPU storage. Growing DIB/readback scratch (~835/~898) loses old backing; `g_SetDIBits` (~866)
  allocates a one-call temporary and never releases it. Risk: create/delete/reupload cycles strand runtime
  host storage and can eventually starve CRT/GL again under a GDI-heavy workload. Suggested repair: reusable
  shared GDI consumer + deletion/resize/temporary frees, allocation-failure checks before dereferences, original
  varied-size bitmap/icon/DIB/replay stress and exact native/browser pixels. Some existing OOM paths dereference
  NULL; fix truthfully, not by fabricating GDI success. This is outside current acceptance per explicit reviewer decision.
