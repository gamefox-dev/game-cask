## 1. Q123: file I/O costs one display frame per read

**Cause (confirmed in code).** Win32 `ReadFile` issues one `asset_range_request` per <= 64 KiB chunk and yields
(`w32_wait_transport`) until it is visible; ABI §12 makes a result visible only at the next `bgt_update`, even for
resident (eager/cached) bytes. The page loop ran at most one pipeline update per rAF tick and none while
`host.ioPending`, so a blocking load was capped at 60 reads/s.

**Fix chosen: transport bursts in the page loop** (not synchronous serving). The guest timeline is defined by the
sequence of updates; serving resident bytes synchronously would remove update boundaries (thread scheduling,
input/timer/audio pumps at `wait_host`, `io.frame`), i.e. change the guest timeline. A burst keeps every update and its
render/request boundary, exactly like back-to-back `step()`, and only lets more of them share one display tick.

- Profile (`w32_core.c`): an update is *time-neutral* until it presents (`w32_guest_present`), snaps a frame
  boundary (`clock_boundary`, `w32_clock_swap0`) or skips time (`w32_sleep_ms`, `w32_idle_ms`). A `w32_wait_transport`
  yield of a time-neutral update sets `yield_kind = 1` for the duration of the suspension; metric
  `guest_time.neutral_yields`. Covers ReadFile/FILE range waits, GL readbacks/shader results, GL host-frame budget
  and GDI record-overflow yields.
- ABI (additive optional export): `u32 bgt_yield_kind(void)` (pipeline driver in `tools/build/pipeline.mjs`);
  `GameHost.transportYield()`. Missing export = 0 = old pacing.
- Runtime (`runtime.ts`, one local method `transportBurst` + `tickTail`): after a pipeline update that ended in a
  transport yield, render it (awaited), settle pending I/O, and run the next update in the same tick, while
  `continueTransport` (`page-pacing.ts`) holds: still a transport yield, tick wall budget < 12 ms (`?ioburst=N`,
  `?ioburst=0` = old loop), and the burst carried < 16667 µs of guest instruction time. Pause/fail/loss/checkpoint
  stop it. `step()` and `measurePage` wait for a running burst (`tickTail`), so tests never overlap an update.
- Observability: page log kind 3 -> `transport_updates`, `max_updates_per_tick` in `game-cask/page-fps/1`
  (additive); test API `pageLoop()` = `{ticks, updates, transportUpdates, maxUpdatesPerTick}`.
- Not done: large read-ahead/prefetch in `RangeFiles`. ABI §12 promises the runtime fetches only chunks touched by
  requests (slice packaging relies on it); prefetch would change that contract. See decisions.

## 2. Q120: glBufferData with size 0

`api_BufferData` accepts size 0 (only negative is GL_INVALID_VALUE, GL 3.3 §2.9.2). `buffer_zero`: a live
CPU-authoritative store keeps its native store as K57 slack (no command), journaled as a command-free `PR_BYTES`
resize record while deferred calls are pending (`pend_resize`), so a replayed rejection restores the size; a
feedback-written store or one beyond the slack budget is released (one deferred DELETE, shared `buffer_release`
factored out of `buffer_store`); `reclaim_slack` releases retained zero-size stores. `HAS_STORE(id)` (gpu && size)
replaces the bare `gpu` checks in uniform ranges, element data, TF capture/begin, attribute and index validation, so
a zero-size store behaves exactly like a buffer without a store. Metric `gl_buffer_zero_stores`. Both backends get
the same wire (none). Tests: native `gl_frontend_driver zero-size` (via `gl-frontend-memory.test.ts`),
`tests/unit/x64-gl-zero.test.ts` (recording stream: 80 zero orphans/frame, 0 CREATE/DELETE, 80 UPDATEs, exact census),
`tests/e2e/gl-zero.spec.ts` (8 guest checks, red pixel after re-specification, census, 1 submit/frame, both backends).

**Census.** `gl_error_calls` unchanged (backward compatible). New sibling `gl_error_codes`:
`{"entry":{"0x500".."0x506"|"other": n}}` keyed by the first error each counted call raised (`call_error` set in
`fail()`); per entry the counts sum to `gl_error_calls`. Per-entry counters became `uint32_t[8]`; the JSON is still one
table loop (K61 Asyncify-size constraint). Documented in ABI §13 K61/K66 paragraphs.

## Coordinator decisions needed

1. **Prefetch/read-ahead** of streamed chunks was not added: it contradicts ABI §12 "fetches only chunks touched by
   requests" (slice packaging). On a real network each uncached chunk still costs one round trip inside the burst.
   Allow a bounded sequential prefetch (not recorded as coverage, never into omitted chunks)?
2. **Burst budget 12 ms** per tick and the one-period guest-time cap are conservative defaults; a heavier load could
   use more of the tick on fast hosts.
3. Bursts also cover mid-frame GL budget/journal transport yields (heavy frames now finish in one tick instead of
   two). Guest-visible state is unchanged; flag if any display-cadence expectation depended on the extra tick.
